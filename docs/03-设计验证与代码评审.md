## P0（必须修）

### P0-1 发声实际为静音：velocity 尺度错配
- 位置：`src/runtime/audio.ts:61` + `schemas/v1/common.json`（vel 0..1）
- 事实链（已对安装版 smplr 1.0.0 源码逐行核实）：smplr 的 `velocity` 是 **0–127 MIDI 尺度**（`midiVelToGain = vel²/16129`，速度分层 `[1,40]…[101,127]`）；本项目按 0..1 语义传 `velocity: 0.75`，**连最弱分层的下限 1 都匹配不上 → 不创建任何 Voice → 无声**；即使 `vel: 1` 增益 ≈ 6.2e-5（约 -84dB）也不可闻。
- 教训：此前浏览器实测只验证了「判定链路 + CDN 可达」，**声音可闻性从未被真正验证**（自动化环境听不到）——此前的「发声链路没问题」结论就此更正。
- 修法：统一为 MIDI 尺度——schema `vel: 0..127`（或代码内做 0-1→0-127 映射），默认 100；给两个示例关卡补 `vel` 字段回归。

## 设计一致性主要发现（详见核查表，此处为要点）

- **[P0] logicPatch 三方断裂**：docs §3.3 承诺 v1 支持（追加规则/覆盖变量初值）、schema 完整定义并放行，运行时零消费（`appendRules?: never[]`）——作者按规范写会静默失效。二选一：补实现（成本低）或删 schema/文档。
- **[P1] lint 体系 5 缺 4**：docs 承诺悬空引用/未声明变量/环检测/绑定路径检查，`LogicEngine.lint` 仅做表达式语法检查。后果：作者拼错路径/事件名全部静默失效。
- **[P1] 未知组件类型整页白屏**：`store.getDef` throw 且无 ErrorBoundary，违反 docs §7「组件缺失降级提示而非崩溃」承诺；`schemaVersion` 运行时被忽略；装载路径（import JSON）不过 Ajv。
- **[P1] `sound.playDone` 幽灵事件**：契约声明但全代码无触发点。
- **[P2] dur 记法三方不合**：schema 放行 `3n/5n/6n/7n`（无效）却拒绝 `16n`（实现支持）；**附点只在音频生效（1.5×），谱面渲染丢附点**——视听不一致。建议 pattern 收敛为 `^(1|2|4|8|16|32)n\.?$` 并渲染支持附点。
- **[P2] 级联预算文档不一致**：docs 说「深度 32」，实现为 maxEvents 64 / maxActions 512，且"深度"与"事件数"非同一度量——改文档对齐实现。
- **[P2] 语义空洞（实现有确定行为但规范未记载）**：多规则按声明顺序执行；条件抛错**整条规则跳过（do/else 都不走）**；未声明变量直接创建；绑定路径缺失时**组件保留上一题旧值**（陈旧谱面比置空更危险）；已 finished 后 next 重复派发 finished；级联中 `q` 是 dispatch 起始快照；`flow.pass` 缺省=通过；`level.started` 带 `{title}` 负载。→ 应补进 docs §3.2。
- **[P2] 组件 id 保留字 `level` 未声明**：作者用 `level` 作组件 id 会被运行器劫持命令。schema 加 `not: { const: "level" }`。
- **[P2] 契约结构缺 state/propsSchema**（ContractDoc 未承载）；`MusicDoc.tempo` 无消费方（播放恒 90BPM）；`resolve()` 把任意 `$` 开头字符串当表达式（`"$100"` 被静默改写，且浏览器装载路径不过 schema）。
- **[P3] 杂项**：`%` 除零无守卫返回 NaN；`&&`/`||` 返回值与 JS 有偏差未记载；`cents(0,…)` 产生 ±Infinity；字符串 `\n` 转义产出字面 `n`；lint 靠错误消息正则区分错误类型（脆弱）；音符选项 >26 个时字母标号溢出；`NoteList`/`Question.data` 无 maxItems（UGC 超大文档冻结渲染）；HomePage 对非法 difficulty 会 RangeError。
