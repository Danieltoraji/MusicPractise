## 1 背景与目标

云盘（docs/31 批次 B2）现为「自存自访」：`cloud_levels` 每用户 10 槽、强 owner 隔离。作为 UGC 平台需打通用户间共享。目标：

0. 资源库管理加强——用户可自建系列（=文件夹），关卡可在系列内外与系列之间移动/复制；支持整文件夹上传云盘（占槽位 = 内含关卡数）。
1. 关卡库——为所有用户提供关卡下载（公共/官方/群组三库），为上传做准备。
2. 公开关卡——云盘关卡可申请公开，管理员审核批准后进入公共关卡库。
3. 精选关卡——公共库子集；申请公开时可一并勾选申请精选；管理员可随时指定/取消任一公开关卡的精选。
4. 官方关卡库——管理后台直传配置。
5. 群组关卡库——用户建群（加入暗号 + 加入密码），群主及其指定的审核员审核群内上传；系统管理员可封禁/强制解散。

「关卡」在上述全链路均包含独立关卡与系列（文件夹）。

## 2 设计裁决（用户确认）

| # | 裁决点 | 结论 |
|---|---|---|
| 1 | 发布更新语义 | **快照制**：审核通过时复制内容快照入库；作者更新云盘需手动「更新发布」重新排队审核。审核所见即用户所得 |
| 2 | 匿名访问 | 公共/官方库**免登录**可浏览+下载（详情端点按 IP 限流）；上传/申请/群组需登录 |
| 3 | 群组加入 | **暗号必填**（全局唯一、可检索分享）+ **密码可选**（设置后必须提供；未设置凭暗号即入） |
| 4 | 前端信息架构 | **双新页**：`#/hub` 关卡库（公共/精选/官方/群组四 Tab）+ `#/cloud` 我的云盘，均入侧边栏；设置页 CloudSection 降级为摘要+入口 |
| 5 | 额度模型 | **按存储域分账**（见 §3） |
| 6 | 系列的地位 | 系列与关卡同为可上传/发布单元；「槽位」统一按关卡数口径 |
| 7 | 重复公开 | 同一 root_doc_id 在同一 scope 仅一条记录（部分唯一索引）；他人下载同 id 再上传申请 → 409「已被他人公开」 |
| 8 | 容器删除语义 | 删除系列/专题只删容器文档，子级回落「未整理」（browse.ts 天然支持，符合文件管理器心智） |
| 9 | 服务端校验边界 | 延续「存储即原文」：信封 schema + 包内闭包检查，不做语义 lint；下载侧走完整 loadLevelDoc 管线 |

## 3 额度模型（按存储域分账）

| 域 | 额度 | 机制 |
|---|---|---|
| 个人云盘 | **10 关/人**（现状不变） | 关卡数口径；系列上传按内含关卡数折算并入 |
| 公共/精选盘 | 不占独立额度 | **源绑定·锁定**：公开期间（含待审）云盘源槽位锁定，DELETE 槽位 409 `publish_locked`（先撤回）；公开库存储 ≤ 个人云盘总量；每人待审 ≤5 条 |
| 群组盘 | **群组独立额度** | 每群 ≤100 关、单成员每群 ≤30 关（关卡数口径）；不占成员个人云盘；建群 ≤3 个/人 |
| 官方盘 | 不占用户额度 | admin 直传，总量上限 200 条 |
| 本地资源库 | 无服务端存储 | 下载进本地 Dexie，不占任何服务端额度 |

锁定规则：待审/已公开 → 锁定；**驳回即解锁**（rejected 仅作历史展示，可重复申请）；撤回删除条目即解锁；「更新发布」期间保持锁定。

容量数学（典型关卡 25KB，50 DAU 满载）：个人 12.5MB + 公共 ≤12.5MB + 群组 10 群×100 关≈25MB + 官方 200 条≈5MB ≈ **55MB，对 D1 5GB 两个数量级余量**。

## 4 数据模型（迁移铁律只增不改不删）

**0005_cloud_folders.sql**（H2）：

- `cloud_folders`：`id`（`cldf_` PK）、`user_id` FK users CASCADE、`folder_id`（系列信封 id）、`title`、`level_count`、`bytes`、`created_at/updated_at`、`UNIQUE(user_id, folder_id)`、idx(user_id)。
- `cloud_folder_docs`：PK(folder_id, doc_id)、`kind` CHECK(series/topic/level)、`payload`（完整信封 JSON）、`bytes`、FK folder CASCADE。

**0006_hub_items.sql**（H3）：

- `hub_items`：`id`（`hub_` PK）、`scope` CHECK('public','official','group')、`item_kind` CHECK('level','series')、`root_doc_id`、`title`、`level_count`、`bytes`、`submitter_id` FK users SET NULL、`submitter_name`（提交时昵称快照）、`submitter_note`、`want_featured`、`status` CHECK('pending','published','rejected')、`featured`、`reject_reason`、`reviewed_by` FK SET NULL、`reviewed_at`、`published_at`、`downloads`、`created_at/updated_at`。索引：idx(scope,status)、idx(scope,featured)、**部分唯一索引 `ON hub_items(root_doc_id) WHERE scope IN ('public','official')`**。
- `hub_item_docs`：PK(item_id, doc_id)、`kind`、`payload`、`bytes`、FK item CASCADE。

**0007_groups.sql**（H5）：

- `groups`：`id`（`grp_` PK）、`name`、`join_code` UNIQUE COLLATE NOCASE、`join_pw_hash`（可空 pbkdf2）、`intro`、`owner_id` FK users CASCADE（群主删号 → 群级联解散）、`status` CHECK('active','banned')、时间戳。
- `group_members`：PK(group_id, user_id)、`role` CHECK('owner','reviewer','member')、`joined_at`、idx(user_id)。
- `ALTER TABLE hub_items ADD COLUMN group_id` FK groups CASCADE + `UNIQUE(group_id, root_doc_id)`。

## 5 API 设计

### 5.1 云盘文件夹（H2）

- `POST /api/cloud/folders`：body `{folderId, title, docs:[{id, kind, payload}]}`。逐文档三道闸（proto 键 → 按 kind 分发信封 schema → 512KB）+ 包内闭包检查（topicIds/levelIds 全部包内可解）+ 槽位合并检查；按 `(user_id, folderId)` upsert 整体替换 docs（事务内 DELETE+INSERT）。body 上限 5.6MB。
- `GET /api/cloud/folders` / `GET /api/cloud/folders/:id` / `DELETE /api/cloud/folders/:id`。
- `GET /api/cloud/levels` 响应追加 `folders` 与合并口径 `used`（= 关卡数 + Σ文件夹 level_count；`CLOUD_LIMIT` 仍 10）。
- 删除端点（levels/folders）增加 live hub 条目检查 → 409 `publish_locked`（H3 起）。

### 5.2 关卡库（H3/H4）

- 匿名：`GET /api/hub/items?scope=&featured=&query=&kind=&limit=&offset=`（仅 published 元数据）；`GET /api/hub/items/:id`（返 `{item, docs[]}` 快照，`downloads` +1，匿名按 IP 哈希限流 30/h）。
- 登录：`POST /api/cloud/levels/:id/publish`、`POST /api/cloud/folders/:id/publish`（body `{note?, wantFeatured?}`；他人已公开同 root → 409；自己已有 → 重置 pending 换快照 =「更新发布」；待审 >5 → 409）；`GET /api/hub/mine`（我的申请全状态）；`DELETE /api/hub/items/:id`（本人撤回，解锁）。
- 管理端（requireAdmin + 审计）：`GET /api/admin/hub?status=&scope=`、`POST /api/admin/hub/:id/approve{featured?}`、`POST /api/admin/hub/:id/reject{reason}`、`PATCH /api/admin/hub/:id{featured}`、`DELETE /api/admin/hub/:id`、`POST /api/admin/hub/official`（直传文档数组为官方已发布，昵称快照「官方」，>200 条 409）。

### 5.3 群组（H5）

- `POST /api/groups`（建群 ≤3/人；409 暗号占用）、`GET /api/groups/mine`、`GET /api/groups/lookup?code=`（需登录）、`POST /api/groups/:id/join{password?}`（密码错 403；失败 5 次/15 分/user+group 限流）、`POST /api/groups/:id/leave`（群主不可退）、`PATCH /api/groups/:id`（群主）、`DELETE /api/groups/:id`（群主解散，级联）、`GET /api/groups/:id`（成员列表）、`PATCH/DELETE /api/groups/:id/members/:uid`（群主任免审核员/移人）。
- 群库复用 hub_items：`POST /api/groups/:id/items`（成员上传，单关或系列 ≤20 关；群库 ≤100 关/成员 ≤30 关超限 409；按 (group_id, root_doc_id) upsert 重置 pending）、`GET /api/groups/:id/items?status=`（成员见 published+自己的；群主/审核员见全部）、`POST /api/groups/:id/items/:itemId/approve|reject`（群主或审核员）。
- 管理端：`GET /api/admin/groups`、`PATCH /api/admin/groups/:id{status}`（封禁/解封）、`DELETE /api/admin/groups/:id`（强制解散）。

### 5.4 横切

- 新写端点全部 `assertSameOrigin`（现有 cloud 端点缺这层，H2 一并补上）。
- 新限流（`worker/ratelimit.ts`）：publish 10/h/user、hub 匿名详情 30/h/IP、join 5 败/15 分。
- 审计新增：hub.approve/reject/set_featured/delete/official_add、group.ban/unban/disband（与操作同成败）。群组审核动作**不写** audit_log（群内自治，有意裁决）。
- D1Fake（`worker/testhelpers/d1fake.ts`）注册 6 张新表与新 SQL 语句。

## 9 边界与已知取舍
