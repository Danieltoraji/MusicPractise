## 2. 发现与修复

### P0（语义错误，已修复）

| # | 问题 | 修复 |
| --- | --- | --- |
| P0-1 | 解析器与生成器的边端口协议不一致：parseBlock 顺序链接 branch/loop 的后继时产生无端口边（connect 会拒绝的图）；生成器 branch 后 `cur=null`、loop 只认 false 边 → if/loop 之后的语句在生成时**静默丢失**。原有往返测试因「先有损、再恒等」而空洞，golden 又恰好都是 branch 在链尾的形状，184 全绿仍未拦截 | 解析器重写为 **exits 出口协议**（parseStmt 返回 `{head, exits}`，branch 无 else 时自带 `{branch,'false'}` 出口，parseBlock 按 exit.port 顺序链接；loop 体出口全部连回循环头且保留出口端口）；生成器 branch case 改为 `cur = joinOf(branch)`（结构化汇合点）顺序继续 |
| P0-2 | 嵌套循环（解析产物）generateScript 必然误报「循环体提前结束」（同端口协议根因） | 随 P0-1 修复，新增嵌套循环 + 循环后语句的往返回归测试 |

生成器新增**结构化汇合点计算**（`joinOf`：true/false 两分支 BFS 距离交集的最小和节点）——`if(c){A} else {B}; C` 的图上两分支尾都连 C，C 即 if 的顺序后继，渲染后顺序继续；两分支汇到不同旧节点（跨结构汇合）仍抛错。`renderIf` 对 false 直指汇合点的形态省略空 `else {}`；parseIf 对空 else 块上传 `{branch,'false'}` 出口保证往返稳定。

## 4. 对后续批次的契约钉死（3-1 执行器必须遵守）

1. branch/loop 缺 false 边 = 该路径处理器结束；
2. emit payload 缺省 = `{}`；call args `[]` = `{}`（migrate 依赖）；
3. loop 体回边 = 指向 loop 节点的入边（无端口语义），loop 的 false 出边 = 循环后继；
4. comment 节点执行直通；on 节点无入边。
