# 关卡编辑器 2.0 设计方案：单一 IR + 三视图

版本 v1.0 · 2026-09-18 · 状态：已评审通过（本轮批次 3-0 起按此实施）

## 1. 背景与目标

现有关卡逻辑 = 事件驱动的 ECA 规则（`LogicProgram`），编辑器以表单（RulesEditor）编辑。本设计将其升级为**面向对象 + 控制流图**模型：

- 组件即实例，方法/事件对关卡逻辑暴露（契约驱动）；
- 关卡即 facade 对象，暴露 `next/restart/finish` 方法与 `level.*` 生命周期事件；
- 逻辑以**节点图**为主编辑面，辅以**伪代码**（面向高端玩家）与 **JSON**（直改）三视图；
- 三视图共享**同一份 IR（GraphProgram）**，不做视图间同步。

## 2. 关键决策记录

| 决策 | 结论 | 论证 |
| --- | --- | --- |
| 旧 ECA 引擎去留 | **图 IR 全面替代**（用户拍板） | 图严格大于 ECA，无法降级编译；双引擎状态分裂。ECA→图编译器保证旧文档无损升级。 |
| 视图同步 | **单一 IR 三投影，拒绝弹窗阻断** | 弹窗是多头数据源的补丁；节点图/JSON 实时生效，代码页保留「应用」（解析需完整程序），IR 异动时黄条提示不阻断。 |
| 图范式 | **执行流 + 内联表达式**，不做数据针 | 复用 expr 引擎（作用域/白名单/预算/校验已成熟）；代码往返无损；连线噪声小。 |
| 脚本语法 | **C/JS 风格大括号**（用户拍板） | 括号显式无缩进歧义，生成/解析/textarea 编辑最稳健。 |
| 执行器 | **第一版即 async**（用户拍板） | `wait(ms)` 节点是音乐时序刚需；后补需重写执行层。 |
| OO 边界 | 不做用户自定义类/继承 | 方法由契约静态定义；「公共方法」= 基座方法。防过度设计。 |
| 空画布 | 节点库模板起步 | 事件节点拖入即带开始桩；降低新手门槛。 |

## 3. 分层架构

```
编辑器三视图
  节点图视图 ⇄ graphOps（IR 纯函数变换）
  代码视图   = generateScript(IR) / parseScript(text)→IR
  JSON 视图  = 整 doc 读写（现状机制）
────────── doc.content.logic = GraphProgram（唯一真源） ──────────
对象层
  ContractDoc v2：methods(command|query) / events 机器可读清单
  ComponentStore：applyCommand（写）+ query（读）
  level facade：next / restart / finish + started/questionLoaded/finished
──────────────────────────────────────────────────────────────
执行层
  GraphEngine（async）：级联队列/预算/generation 沿用 LogicEngine 机制，
  执行单元 = 事件处理器子图（从 on 节点沿执行边行走）
```

## 4. 对象层

### 4.1 契约 v2（`componentDef.ts` 扩展）

```ts
interface MethodDef {
  name: string
  kind: 'command' | 'query'   // command=改状态出效果；query=读状态有返回值
  params: { name: string; type: 'number'|'string'|'boolean'|'json'; optional?: boolean }[]
  returns?: 'number'|'string'|'boolean'|'json'
  desc?: string
}
interface ContractDoc {
  type: string; displayName: string; category: 'music'|'ui'|'hidden'
  methods: MethodDef[]
  events: { name: string; payload: Record<string, string> }[]
  // bindings / propsDoc 保留
}
```

- 现有 11 类组件的 commands 全部转为 `methods(kind:'command')`；
- 新增查询：`input.getValue()` `slider.getValue()` `rhythm.getTaps()` `tuner.getReading()` `timer.getCount()`；
- `ComponentDef` 增加可选 `query(state, method, args): Json`；`ComponentStore.query(id, method, args)` 供执行器调用；
- **基座公共方法**（所有实例继承，节点库自动陈列）：`setVisible(b)`、`setEnabled(b)`；move/resize 运行时方法后置。

### 4.2 level facade（伪实例，id=`level`）

- 方法：`next()`、`restart()`（已有）、`finish(passed?)`（新增，主动结算，幂等守卫沿用）；
- 事件：`level.started`、`level.questionLoaded`、`level.finished`（已有）；restart = 会话重建并重发 started，不设独立 reset 事件。

## 5. 逻辑 IR：GraphProgram v2

```ts
interface GraphProgram {
  logicVersion: 2
  variables?: Record<string, Json>
  nodes: GNode[]            // 数组顺序 = 事件处理器注册顺序
  edges: GEdge[]            // 执行边
}
interface GNodeBase { id: string; x?: number; y?: number }   // 位置仅视图用
type GNode = GNodeBase & (
  | { kind:'on';      event: string }                                   // 事件入口，无入边
  | { kind:'assign';  target: string; value: RValue }                   // v.x = …
  | { kind:'call';    target: string; method: string; args: string[] }  // args = expr 源文本
  | { kind:'emit';    event: string; payload?: Record<string, string> } // 内部事件「名:名」
  | { kind:'branch';  cond: string }                                    // 出边带 port 'true'|'false'
  | { kind:'loop';    mode:'while'|'repeat'; cond?: string; times?: string }
  | { kind:'wait';    ms: string }
  | { kind:'comment'; text: string }                                    // 无执行语义
)
type RValue = { expr: string } | { call: { target: string; method: string; args: string[] } }
interface GEdge { id: string; from: string; to: string; port?: 'true'|'false' }  // 无出边=处理器结束
```

节点语义定式：

1. **args/payload 一律是 expr 文本**（含对象字面量）→ 代码往返无损；
2. **查询方法只出现在 assign 右侧**（`v.cents = tuner1.getReading()`），表达式本体保持无副作用；条件中要用查询 = 先赋值再判（两行）；
3. **loop = 带内部状态的 branch**：真→体、假→false 边、体沿边回到 loop 成环；死循环由节点预算兜底（报错不卡死）；
4. 同一事件多个 on 节点：按 nodes 数组顺序依次执行（ECA 同语义）；
5. `branch` 可缺 false 边（= 条件不满足直接结束）；`loop.repeat` 次数尽走 false 边。

**expr 引擎唯一扩展：对象字面量** `{ key: expr, … }`（仅表达式位置；`{}` 合法；键为标识符）。覆盖 payload/args 需要对象结构的场景。

## 6. 伪代码语言「LevelScript」（C/JS 风格）

```ebnf
program   = { handler | comment } ;
handler   = "on" , ident , block ;
block     = "{" , { stmt } , "}" ;
stmt      = assign | callstmt | if | while | repeat | wait | emit | comment ;
assign    = "v" , "." , ident , "=" , ( expr | invocation ) ;
callstmt  = invocation ;
invocation= ident , "." , ident , "(" , [ expr , { "," , expr } ] , ")" ;
if        = "if" , "(" , expr , ")" , block , [ "else" , ( if | block ) ] ;
while     = "while" , "(" , expr , ")" , block ;
repeat    = "repeat" , "(" , expr , ")" , block ;
wait      = "wait" , "(" , expr , ")" ;
emit      = "emit" , string , [ object ] ;
comment   = "//" , …行… ;
expr      = 现有 expr 同文（含对象字面量）
```

- 保留字：`on if else while repeat wait emit true false null`；分号可选（生成器不写，解析器容忍）；字符串单双引号皆可。
- 注释语义：**独立成行的 `//` 注释提升为 comment 节点**（IR 往返保留）；语句行尾注释不进入 IR。
- 结构化边界（图语言自由，伪代码覆盖结构化子集）：分支汇合到公共后继 = 合法的 if/else 顺序后继（生成器用 BFS 距离交集求汇合点）；跨结构汇合、循环体掉出（体末尾不回到循环头）、从循环体跳出三类结构无法语句化，generateScript 抛错并提示改用节点图编辑。
- 语句与节点一一对应（双向转换无损的根据）。
- 解析器 = 递归下降**语句层**；表达式直接复用 `parseExpr`；错误带行列号（`ScriptError`）。

示例：

```
// 听音点击
on level.started {
  v.score = 0
}
on staff1.noteClicked {
  if (event.midi == q.data.target) {
    sound1.play(q.data.rewardChord)
    v.score = v.score + q.scoring.max
  } else {
    sound1.play([{ midi: 60 }])
  }
}
on input1.submitted {
  v.guess = input1.getValue()
  while (len(v.guess) < 3) { emit 'app:hint' { left: 3 - len(v.guess) } }
  wait (500)
}
```

## 7. 执行器 GraphEngine（3-1 批次）

- 沿用机制：级联事件队列（maxEvents 64）、**节点预算 maxNodes 512**、expr 步数预算 1000、generation 计数、变量存储、错误隔离（单节点失败→本处理器中断 + onError 上报，其它处理器不受影响）；
- `dispatch(event, payload)` API 不变（fire-and-forget async）；处理器 = 从 on 节点沿执行边的 async 行走；`wait(ms)` = setTimeout promise，**每次 await 返回后检查 generation**（reset/restart 即刻作废进行中的执行）；
- timer 效果通道保留，与 wait 并存：timer = 外部节拍，wait = 逻辑内时序；
- 结算：`finish()` 幂等守卫、`flow.pass.expr`、`v.score` 约定全部保留。

## 8. 三视图同步

- 唯一真源：`doc.content.logic`（GraphProgram）；
- 节点图：编辑操作 = graphOps 纯函数 → update(doc) → 全视图即时刷新；节点位置存 `x/y`；
- 代码：进入时 generateScript；编辑后「应用」→ parseScript → IR；解析失败显示行:列错误且不动 IR；IR 在其它页被改且代码文本有未应用修改 → 黄条提示（重新生成 / 强制应用），不弹窗；
- JSON：现状机制（应用时 doc.id 锁定）。

## 10. 迁移（schemaVersion 1 → 2）

规则映射：

| ECA | GraphProgram |
| --- | --- |
| `Rule { on }` | `{ kind:'on', event:on }` 节点 |
| `when[]` 全部 AND | 后接 `{ kind:'branch', cond: when 逐项加括号后 join(' && ') }`（保优先级）；else 链接 false 边 |
| `do`/`else` 动作序列 | 沿执行边的节点链 |
| 无 when 的规则 | else 在 ECA 语义下是永不执行的死代码，迁移时**丢弃**（行为等价），do 直连 on |
| `{ cmd, args }` | `{ kind:'call', target, method, args: jsonToExpr… }`（args 缺省 → `[]`；非对象 args 包装为单参数） |
| `{ set, expr }` | `{ kind:'assign', target, value:{expr} }` |
| `{ emit, payload }` | `{ kind:'emit', event, payload: jsonToExpr… }` |

Json 参数 → expr 转换（`jsonToExpr`）：`"$q.data.x"` → `q.data.x`；`"$v.x"` → `v.x`；`"$event.x"` → `event.x`；`"$expr:E"` → `E`；标量 → 字面量（字符串加引号转义）；数组 → `[…]`；对象 → `{…}` 递归。

- 装载与导入管线自动升级（loadLevelDoc 挂 migrate）；8 个内置关卡源文件直接改写为 v2；`ensureSeeded` 会把 builtIn=1 记录刷成 v2；用户自建 v1 文档读取时透明迁移；
- Golden 测试：关键关卡 v1/v2 双跑对比变量终态与事件序列（3-1 执行器就位后）；
- 已知限制（评审确认，8 内置关卡均不涉及）：非对象 emit payload（标量/数组）迁移后包装为 `{value: …}`，事件负载形状改变；cmd 路径非两段时迁移抛错。
