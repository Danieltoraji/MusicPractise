# 26 · 取消绑定机制与节点图应用行数据

> 状态：已落地（批次 1-4 全部完成，测试 359/359）。
> 提交链：`4d22e0b`（引擎层）→ 编辑器层 → `11f46e6`（lint 格式判断）→ 收口。

## 1. 背景与动机

v3 早期架构中，数据表字段进入组件的通路是**静态绑定**：组件实例上声明
`bindings: { text: "$q.title" }`，`LevelSession.applyBindings` 在 `setView`/`loadRow`
两个时机用 `engine.resolve` 解析后写入组件状态，编辑器在画布 Inspector 提供「数据映射」
文本框。实践反馈问题重重：

- 绑定是**隐藏数据流**：组件的数据来源在画布属性里，与节点图（逻辑的唯一真源）割裂，
  排查「为什么文案不刷新」需要跨三个面板拼线索；
- 三个绑定槽位（label.text / choice.options / staff.music）之外无法复用；
- 无任何格式判断：音符列喂给文本标签、文本列喂给选择器都在运行时静默失效。

## 2. 裁决（用户确认）

1. **载体形态：复用 `call` 节点 + 新增 set 命令**。不新增 IR 节点种类；label/choice/staff
   各增加一条标准命令（与 `button.setText` 命名对齐），NodeInspector 按 `(target, method)`
   做第三种参数特化（前两种：`views.goto` 视图下拉、`PlayArgsEditor` 音符编辑）。
2. **存量兼容：自动迁移**。迁移器把 bindings 编译为图节点，与 `logicPatch → 行门控子图`
   同一模式；schema 保留废弃字段保证旧档装载（「先放行后清洗」，docs/25 P0 教训）。

## 3. 新语义：应用行数据 set 命令

| 命令 | 参数 | 可接受列类型 | 收敛规则 |
|---|---|---|---|
| `label.setText` | `{ text }` | text / number / boolean | 数字/布尔 → `String`；对象/数组 → 忽略 + console.warn |
| `choice.setOptions` | `{ options }` | list（json 需存字符串数组，软提示） | 非字符串项 `JSON.stringify`；重放时 `revealed` 复位 |
| `staff.setMusic` | `{ music }` | json（存 MusicDoc 对象）；**docs/27 起扩展为 json / notes（直收音符串数组，包装 `{notes}`）** | 非对象忽略 + console.warn |

收敛语义与被移除的 `applyBinding` 逐条对齐（唯一的差异：静默丢弃升级为 console.warn）。

**应用时机（与原 applyBindings 对齐）**：迁移器为 bindings 生成**两个事件入口、各自独立的
set 命令链**：

- `on question.loaded → call×N`——换行/跳行后应用（row 必已就绪，无需守卫）；
- `on view.entered → branch(q != null) → call×N`——进视图时重放；守卫吸收
  `start()` 中 `setView` 先于首次 `loadRow` 的时序（首帧 `q` 为 null，分支不放行）。

**作者手写规范**：新的应用行数据节点请挂在 `question.loaded` 或 `view.entered` 上。
不要在同一条链上 `assign v.__row` 之后再读 `q.*`——`q` 是 handler 起点的快照（docs/25 §4
边界备忘），那时拿到的还是旧行。

**约定**：`DATA_APPLY_COMMANDS` / `DATA_APPLY_ACCEPTED_TYPES` / `COLUMN_TYPE_LABELS`
定义在 `engine/level.ts`，为迁移器、节点图 Inspector、lint 三方**单一真源**，改矩阵只改一处。

## 4. 迁移器规则（`migrateDoc.compileBindingsToNodes`）

- **槽位映射**：`label.text→setText`、`choice.options→setOptions`、`staff.music→setMusic`；
  其余槽位在旧运行时本就是 no-op，丢弃 + console.warn。
- **值转换**：复用 `migrate.jsonToExpr`——`$q.x`/`$v.x`/`$event.x` 去前缀为表达式、
  `$expr:` 去前缀、字面量转表达式字面量；无法转换（控制字符等）丢弃 + 警告。
- **节点形态**：call 参数 = 单对象字面量 `{ text: q.title }`（引擎约定 `argv = args[0]`）。
- **不共享链节点**：两个入口各自持有一条独立 call 链。script 伪代码视图按处理器遍历
  渲染，跨处理器共享节点无法文本化（golden 往返实测丢节点）——迁移产物必须落在
  script 可表示子集内。
- **幂等**：转换后从组件上剥离 `bindings`；二次装载零追加（golden 断言覆盖）。
- **id 分配**：`bnd_q_/bnd_v_` 前缀 + 组件/方法名，与既有图撞车时数字后缀（确定性），
  不像 logicPatch 前缀那样抛错——bindings 转换在每次装载都会尝试，抛错会砖化旧档。
- **schema 兼容**：`Component.bindings` 与 `BindingValue` **保留**在 schema 中（标注废弃），
  迁移器剥离。直接删字段 = 旧档被 Ajv 拦截（docs/25 §3 P1 教训）。

## 5. 格式判断（三层）

1. **Lint 静态检查**（`lintGraphProgramDetailed` 第 4 区）：`GraphLintCtx` 新增
   `componentTypes` 与 `tableColumns`，GraphEditor 与 LevelSession 装载 lint 均传入。
   对组件 `call` 节点命中数据应用命令时，剔除字符串字面量后扫描 `q.<列>` 引用：
   - 列不存在 → `dangling-ref`（数据表没有列 "x"）；
   - 列类型与矩阵不符 → `structure` 警告（指明期望类型）。
   旧调用方（ctx 缺字段）自动跳过，零破坏。
2. **Inspector 内联提示**（`TableFieldPicker`）：列下拉每项带类型徽标（`标题（title）· 文本`），
   选中列类型不符时显示 ⚠ 提示（同一矩阵）。
3. **运行时收敛**：见 §3 表格；宽松收敛 + 警告，绝不抛错卡死关卡。

## 6. 移除清单（机制本体）

`ComponentInstance.bindings`、`ContractDoc.bindings`、`ComponentDef.applyBinding`、
`ComponentStore.applyBinding`、`LevelSession.applyBindings` / `warnOrphanBindings`、
`GraphEngine.resolve`（v1 引擎 `logic.ts` 的 resolve 保留，属遗留兼容面）、
画布 Inspector「数据映射」表单与 bindings JSON 高级区。列信息反哺编辑器：数据表列注入
`refPaths` 与 expr datalist，assign 引用模式 / 条件构造器 / 全部表达式输入均可下拉选列。

## 7. 边界备忘（记录在案）

- 迁移节点无画布坐标（与 logicPatch 编译产物同惯例），打开节点图可用自动排版整理。
- 数据应用命令现在作用于**全部组件**（不限于当前视图组件——store 状态与挂载解耦），
  进视图重放由 view.entered 链兜底；行为是原机制的超集。
- 内置样例 6 个含绑定关卡已按迁移器产物重建（note-click / theory-choice / timed-reaction /
  clef-test / synth-lab / tutorial-hello）；v1 夹具不动，继续作为迁移管线的输入。
- golden 等价测试：v1 引擎时代 bindings 由 LevelSession 在引擎外应用，v1 引擎从不产生
  set 命令——命令序列对比按 v1 夹具的 bindings 精确剔除 v3 侧新增命令后比较。
