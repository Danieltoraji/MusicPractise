# 33 · 运行时排查：听音点击时序错乱 / 点击延迟 / 五线谱黑框与滚动

> 批次：运行时维护（bug 排查三连）。范围仅执行器与组件视图，不动关卡数据格式。
> 结论先行：三个 bug 的根因**全部在执行器/视图侧**，关卡数据格式（docs/27 音符串时序模型）没有问题。

## B1 · 听音点击关卡发音时序错乱

**现象**：部分听音点击关卡（note-click、melody-dictation 等在 `question.loaded` 自动 `sound.play` 的关卡）发音时序错乱，尤其刷新页面直接进关后首次交互时，多个音同时炸响。

**根因（执行器侧，`audio.ts`）**：`getCtx()` 对挂起的 AudioContext 只做 fire-and-forget 的 `ctx.resume()`，而 `playNotes` 的排程链在采样就绪后直接取 `ctx.currentTime + 0.06` 作时间基准。浏览器自动播放策略下（无手势创建的上下文处于 `suspended`），`currentTime` **冻结**：

1. 进关自动播放把音符排在冻结时刻 `F+0.06`；
2. 用户手势解锁前的一切 play 全部堆叠在同一个冻结时刻（时钟不走，偏移量全是 0）；
3. 首次手势 `resume()` 成功的瞬间，堆叠的事件全部到期 → 一个音的旋律同时炸响、新旧序列互相叠置 → 「时序错乱」。

**判定**：关卡数据无问题（`scheduleNoteEvents` 的 t/接排语义与 docs/27 一致）；错乱发生在「排程时刻」而非「时序计算」。执行器修复：

- 新增 `ensureRunning()`：排程前等待上下文进入 running——先试 `resume()`，被拒（无手势）则挂 `statechange` 等待解锁；`state` 不可读的替身上下文直通（测试友好）。
- `playNotes` / `playSynth` 统一经 `ensureRunning` 取时间基准，音符内部时序（`startBeat × spb`）不变。
- 新增播放代数守卫（`playNotesGen` / `synthGen`）：排队等待解锁期间发生过 stop 的播放静默作废，杜绝「解锁后幽灵音再响」。
- `SOUND_DEF.stop` 此前**契约承诺但未实现**（静默 no-op），现在产出 `audio.stop` 效果 → `stopAllAudio()`：作废排队播放 + 停掉全部采样器声部（smplr `stop()`）+ 合成器静停（`stopSynth`）。重听/换题前先 stop 即可清掉上一轮余音。

**遗留说明**：节奏组件（RhythmView）的节拍器仍直接在 `ctx.currentTime` 排程——它的 start 由按钮手势触发，解锁早已完成，不在本批范围。

## B2 · 部分点击发音有延迟

**现象**：钢琴类点击（staff 音符 `__strike`、fingering 键、sound 组件）偶发明显延迟，合成器点击即时。

**根因（执行器侧）**：smplr 采样器按需加载——**首次 play 才开始下载**，SplendidGrandPiano 全音域 **169 个采样文件**（实测每文件约 1s、并行下载仍需数秒，弱网更久）；`playNotes` 等采样全部就绪才排程，首击在下载完成前是无声的。次要因素：挂起上下文首次 `resume()` 的毫秒级延迟（B1 修复已顺带消除冻结堆叠）。

**修复**：

- `audio.ts` 新增 `preloadAudio(instruments)`（幂等）；`audioHost.ts` 新增 `preloadLevelAudio(doc)`：扫描组件清单——staff/fingering 预热钢琴，sound 按 `props.instrument` 精确预热（未知值回落钢琴）；`LevelRunner` 挂载即调用。下载不依赖用户手势，进关瞬间即开始，首击即响。
- **音色透传修复（批次13 回归）**：`runAudioEffects` 此前丢弃 `eff.instrument`，电钢/木琴全部回落钢琴；现已透传。
- 顺带：`ensureSampler` 装载失败此前被静默吞掉（「点了没声音」无从排查），现在 `console.warn` 留线索；钢琴单例与 `ensureSampler('piano')` 合并进同一注册表（此前 `stopAllAudio` 遍历注册表看不到独立钢琴单例）。

## B3 · 五线谱：音符四周黑色框 + 长谱面无法左右滑动

**现象**：运行时里每个音符外面套着一个竖长黑框；宽于 800 设计坐标系的谱面（如 clef-test 的 `layout.w=1900`）右侧被直接裁掉，无法横向滚动（题面却写着「谱面可横向滚动」）。

**根因 1（黑框）**：批次12 的音符热区垫（`rect[data-hitpad]`，`fill="transparent"`）追加进 `g.vf-stavenote` 组内。SVG 的 `fill`/`stroke` 是**可继承属性**，VexFlow 在音符组上设置的黑色描边被垫继承 → 每个热区被画成 39×176 的黑框。修复：垫显式 `stroke="none"`。

**根因 2（无法滚动）**：批次12 共享舞台 `.stage-viewport { overflow: hidden }`（index.css 尾部）与旧 `.level-canvas-wrap { overflow-x: auto }`（头部）同特异性、前者靠文件位置获胜 → 计算样式 `overflow-x: hidden`，宽内容被裁。修复：`.stage-viewport` 改 `overflow-y: hidden; overflow-x: auto`——fit-scale 已保证 800 设计系纵向不出界，宽内容（长谱面）恢复横向滚动；删除被覆盖的死规则 `.level-canvas-wrap`。窄屏（scale<1）下长谱面同样按比例缩小后可滑到全部音符，不再被压扁丢失。

## 验证

- 单测：新增 `audioSuspend.test.ts`（冻结时钟回归：挂起不排程/解锁按 running 时钟重排/stop 作废排队播放/running 行为不变/instrument 透传/预热扫描）+ `sound.test.ts` stop 契约 + `views.test.tsx` 热区垫 `stroke=none`；全套 679 绿。
- 浏览器实测：黑框消失、横向滚动条出现且可滚到谱尾（scrollLeft=maxScroll）、点击音符（对/错分支）音频链路零 console 报错。

## 遗留问题复核：RhythmView 节拍器（2026-10-12 第二轮，结论：需要修，已修）

B1 修复时曾以「rhythm.start 由按钮手势触发」为由把 RhythmView 排除在挂起安全改造之外——**该前提不成立**：

- **无手势触发路径真实存在**：`rhythm-follow.level.json` 把 `rhythm1.start` 挂在 `question.loaded` 上，`LevelRunner` 挂载即 `session.start()`——刷新页面/深链直进 = 零手势，整轮节拍器在挂起的冻结时钟上预排。编辑器侧 AI `debug_control(start)` 与 `debug_dispatch("question.loaded")` 同样可无手势触发，且调试画面真实出声。
- **与 B1 的语义差异（为何当年没炸）**：RhythmView 是单锚点整轮预排（t0/grid/RAF tick/tap 全部读同一 `ctx.currentTime` 与同一 `t0Ref`），挂起时内部完全自洽——整轮静默**推迟**到首次手势（resume 后时钟从冻结值继续，预排的 click 依序正常响），不会像 `playNotes` 的多次独立调用那样在冻结时刻上互相堆叠炸响。因此它是「推迟 + 迷惑」而非「错乱」。
- **实际缺陷**：①解锁等待期间 UI 已显示 TAP 活跃、节拍点死在 -1，「点了没反应」无从解释；②`tap()` 守卫只有 `runningRef`（effect 排程即置 true），解锁前的盲拍以恒定负值（冻结时刻 − t0）进入判分——刷新后立刻拍打板 = 一记无参照的垃圾 tap；③违背本批建立的执行器不变量「所有音频排程在 running 时钟上进行」。

**修复**（与执行器同语义，低危加固级）：

- `audio.ts` 把私有的 `ensureRunning()` 以公开名 `readyContext()` 导出。
- `views.tsx` RhythmView effect：`readyContext().then(ctx => …)` 等进入 running 后才取时间基准锚定 t0 并预排整轮；effect 闭包 `cancelled` 标记防解锁前换轮/卸载的竞态；`runningRef.current = true` 移到排程落定之后（盲拍不再放行，tap 守卫本身不变）；新增 `live` state（排程落定置位、roundDone/停止/清理复位），打板垫文案与 `live` 样式改由它驱动——等待解锁期间诚实显示「未开始」。
- **不改**：RhythmDemo 页（#/rhythm，按钮手势兜底，即使 resume 竞态也内部自洽、毫秒级推迟无感）；`audioHost.nowSeconds()`（供 wait/定时表达式取时钟，挂起时停摆属「暂停」语义，与画面冻结一致）。

**验证**：`views.test.tsx` 新增 2 用例（挂起时 start 不预排/盲拍不放行/「未开始」，解锁后 6 click 按 spb 精排于 running 时钟、tap 相对 t0；running 时 start 立即排程的既有语义回归）；全套 681 绿 + tsc/build 干净。浏览器侧：本仓库使用的内嵌 Chromium 无自动播放限制（新建上下文直接 running），挂起路径无法在该环境肉眼复现，以单测为准；running 路径复核正常（节拍点渲染、整轮自然结束、零 console 报错）。
