## 4. 必须返工的 P1 级问题（6 项）

### 4.1 [R6/E1 新回归] 脚本应用后**无法保存**：合并结果写入 `x: undefined`

- **证据**：`src/engine/script.ts:892-896` 对配对成功的节点执行 `{...n, id: prevId, x: prevNode.x, y: prevNode.y}`——旧节点无坐标时，结果对象带上**显式 `x: undefined` / `y: undefined` 属性**；`loadLevelDoc` 的 cfworker 校验器遇到 undefined 属性直接抛异常，且 `validateEnvelope` 未 try/catch（`src/library/validate.ts:61-71`）。
- **触发面**：迁移旧关 / 点组件库新建 / AI `write_script` 等**无坐标的图** → 打开脚本页 → 应用（即使不改文本）。保存报 `保存失败：Instances of "undefined" type are not supported.`；AI 写工具与 `run_level` 预检一并失败。
- **对照实验**：仅剔除 undefined 键即通过校验。**这是本轮修复引入的新 P1**，直接击穿「脚本页编辑 → 保存」主链路。
- **修复建议**：合并时条件写入（`...(prevNode.x !== undefined ? {x:prevNode.x} : {})`）；`validateEnvelope` 包 try/catch 转为可读错误；补「无坐标旧图应用脚本后可保存」回归。

### 4.2 [R6/E1 新回归] 脚本二次应用产生**重复节点 id / 自环边**，可静默入库

- **证据**：`mergeScriptAnchors` 对未配对的 next 节点保留 parse 产物 `sN` id，而配对节点又可能映射到旧图的 `sN` id（旧图由上一次脚本应用产生时 id 恰为 `sN`）→ 重复 id。Lead 复现：`on` 内 `a=1,b=2,c=3` 首次应用后，第二次改为 `b=2,x=9,a=1`（重排+插入+删除）→ 合并结果 `dup: ['s3']`；节点图侧复现为 `["s1","s2","s3","s3"]` 且边塌缩成 `s3→s3` 自环。
- **后果**：lint 只给一条红标；`loadLevelDoc` 的重复 id 预检只覆盖组件/视图/表列（`validate.ts:158-171`），**不查 logic 节点 id** → 可保存入库；`graphEngine` 的 `byId` 后者覆盖前者（`graphEngine.ts:97-101`）→ 运行执行错节点。
- **修复建议**：合并结果强制 id 唯一性（保留 id 冲突时回退到新 id）、边端点去重、`findDuplicateIdErrors` 增加 logic 节点/边 id 检查；补对抗测试（重排/插入/删除/重复语句/s 前缀旧图）。
- **关联**：`ScriptTab` 无条件显示「节点 id 与坐标已保留」，`unmatched` 计数未消费（`ScriptTab.tsx:101-107`），用户被误导。

### 4.3 [R7/F1 未闭环] AI 运行期仍会静默覆盖创作者手改，且**零警告**

- **真实场景**：AI 写 #1 → 用户手改标题 → AI 写 #2。写 #2 仍基于旧 `runDoc` 生成整文档回写（`tools-write.ts:40,48`），用户改动被覆盖。
- **检测为何失效**：`lastSeenExternal` 在每次 `applyDoc` 时被刷新为「当刻编辑器 doc」（`agent.ts:118-122`），随后检测比较 `external !== runDoc && external !== lastSeenExternal`（`agent.ts:163-172`）——主场景在 apply 瞬间 lastSeenExternal 已被置为被覆盖前的用户版本，检测恒假。只有「apply 之后、检测之前」的微窗口（测试构造的场景）能触发警告。
- **动态证据**（Lead）：mock agent 循环中在第二笔写前手改标题 → 最终 `{warned:false, kept:false}`（无警告、改动丢失）。R7 单测（`agent.test.ts:625-655`）在 tool.exec 内 apply 后再改 external，仅断言警告文案，未断言用户修改保留。
- **附加**：警告后 `read_doc/read_script/read_json` 仍读影子 `runDoc`（`tools.ts:54/80/148`），「请重读」在同一 run 内无效。
- **修复建议**：写工具 apply 前对比「编辑器最新 doc 引用/hash vs runDoc 基准」，不一致则阻断回写或合并；读工具在冲突态优先读实时 doc；补「用户先手改、AI 后写」用例并断言用户修改保留。

### 4.4 [R5 新回归] AI 调试工作流被自身生命周期修复打断

- **路径**：AI 调 `debug_control(start)` → `GraphEditor` 切调试布局（`GraphEditor.tsx:1001`），编辑布局的 AiPanel 卸载（`:860` → `:1077`）→ AiPanel 卸载 cleanup `stopAgent(doc.id)`（`AiPanel.tsx:92`）。
- **实测**：`stopAgent` 的 abort 落在两次 fetch 之间，当前 run 未立即结束，但 `ctx.signal` 永久 aborted → 之后 `debug_dispatch` 恒返回「已停止：事件未触发」，会话仍 `running(owner=ai)`；「AI 自主驱动调试、用户切图观察」工作流（docs/30 §5.1/§6.3/§6.4）被破坏。根因：`client.ts:183-186` 发起 fetch 前不检查已 aborted，`agent.ts` 循环也无 aborted 检查。
- **同类**：AI 运行中切「节点图」Tab（外置 AiPanel 卸载）→ run 被中止；docs/41 未记录这一行为变化，与 docs/28「全 tab 常驻」冲突。
- **修复建议**：运行归属上移到 EditorPage/EditorRuntime，布局切换不 abort；只在显式关闭面板/离开编辑器时停止（可加确认）；循环每轮检查 aborted 并清理；补「AI 启动调试后切图」端到端用例。

### 4.5 [R2/A1 未闭环] 内置示例保存的 await 窗口仍会静默覆盖期间编辑

- **证据**：内置分支无条件 `setDoc(saved)`、`setDirty(false)`（`EditorPage.tsx:281-295`）；普通路径已有 `docRef.current === latest` 判定（`:297-310`），内置分支没有。
- **动态证据**（Lead）：mock 慢速 `put`（250ms），保存期间改标题 → 完成后标题回滚为「内置示例（副本）」、脏标消失；落库与 UI 均丢失该编辑。原 P1 A1 的核心场景之一仍未闭环。

### 4.6 [R4/C5 新回归] 内置副本保存后的「假外部修改横幅 + 一键覆盖」，以及 undo 身份回退

- **假横幅**：内置示例另存副本后，`record` 仍是内置记录（v0.1.0），而 `baselineVersionRef` 已前移为副本版本（v0.1.1）→ `externalChanged` 恒真（`EditorPage.tsx:280,289,367-369`），实测出现「⚠ 文档已在其他窗口被修改（库内版本 v0.1.0）」。
- **破坏性按钮**：该横幅的「加载外部版本（覆盖当前编辑）」直接 `setDoc` 且无 confirm、不入撤销栈（`:411-433`）→ 一次点击即可把副本上的未保存编辑覆盖回内置模板；叠加假横幅后误点概率高。
- **undo 身份回退**：保存内置副本只 `setDoc(saved)`，历史栈仍保留内置原档引用 → 保存后 Ctrl+Z 会把 `doc.id` 退回内置 id（实测标题从「内置示例（副本）」变回「内置示例」），而 URL 仍是副本 id；此后再保存会因 `existing.builtIn=1` **另建第二份副本**。
- **消费方错位**：ai session/checkpoint（按 `doc.id`）、`draftStore` 四槽、runLog/调试断点都仍指旧内置 id → 对话清空、↩回滚消失、JSON/表格布局草稿失联（一次内置副本保存即可触发）。
- **修复建议**：内置分支前移后同步排除 A8 横幅；「加载外部版本」加 confirm 且走 `update`（可撤销）；换 id 时重写/清理 id 键控状态（session/checkpoint/drafts/log），或明确接受并在 UI 提示；补「保存内置副本后 Ctrl+Z / 立即再保存」用例。
