# 35 · UI 重构与皮肤系统（文档页 + 主题令牌化 + 皮肤中心 + 三套预设皮肤）

> 状态：落地中。目标：**不改变任何现有功能与逻辑**，仅重构显示层；补全显示需求；关键完成后对显示正确性、功能不受影响做多轮验证。不碰生产端。

## 0 · 背景与目标

1. 新增「文档」功能页（`#/docs`），入口与「首页」「资源库」平级；版式参考 api-docs.deepseek.com（左侧分组目录 + 正文 + 翻页），目的：**补全显示需求**（目录、文章排版、表格、代码块、提示框、翻页器等新界面形态）。
2. 考察现有 UI，整理显示需求清单（§2）。
3. 新 UI 布局规划：布局因地制宜（不改信息架构），以下维度**可随皮肤变化**：
   - a. **配色**：纯色与渐变均支持；背景/文字/元素的色值全部可改。
   - b. **字体**：本机字体可用；考虑用户机器缺字体的问题——皮肤自带**回退字体栈**，并支持在皮肤中心**本地导入字体文件**（FontFace + IndexedDB 持久化，等效「皮肤资源」的落地形态；云端字体下载留作后续）。
   - c. **背景图**：整体界面 / 仅主界面（首页）二选一；可换图、调透明度。**本地生效，不同步云**；默认无；设置后对应区域的默认背景色被图片替代。
   - d. **水印图**：叠加在背景色/背景图之上、界面元素之下的装饰层；可换图、调透明度、显示位置（平铺/居中/四角）、四周渐隐程度。**本地生效，不同步云**；默认无。
4. 「皮肤中心」（`#/skins`）：选择预设皮肤（差异=配色+字体）；在预设之上可叠加自定义背景图/水印。
5. 三套预设皮肤（§5）：音乐梦旅 / 紫色清春 / 堇庭流华。

## 1 · 现状考察（UI 审计结论）

- 样式集中在 `src/index.css`（约 4900 行）。已有 10 个全局 token（`--bg/--panel/--ink/--muted/--line/--accent/--accent-ink/--ok/--bad/--warn`），主要面板类已大量引用；编辑器节点图工作台有独立 `--ge-*` 深浅双主题（`.ge-light/.ge-dark`），**不在本次改造范围**（保持编辑器功能与外观体系不动）。
- 仍有约 180 处硬编码色值散布在页面镶边：hero 渐变（`#eef2ff/#fdf4ff`）、标签/徽章底（`#eef0f7`）、表头底（`#fafbfe`）、代码块（`#14181f/#d7dce5`）、软色底（warn `#fffbeb`、ok `#f0fdf4`、bad `#fef2f2`）等——这是换肤的**主要阻力**。
- 路由为 hash 路由（`src/App.tsx`），顶栏导航：首页 / 资源库 / 校音器 / 节奏 / ⚙设置；页面组件全部走 token 或局部类，无全局 UI 框架。
- 关卡舞台（800×470 纸面、五线谱、comp-\* 组件）属**内容层**：保持纸面浅色语义，不随深色皮肤翻转（乐谱可读性优先）。
- CSP（`public/_headers`）：`img-src data:`、`font-src 'self' data:` 已放行 dataURL 图片；字体经 `FontFace(ArrayBuffer)` 注入不触发 fetch，不受 CSP 限制。
- 测试：vitest + jsdom + fake-indexeddb；现测试不断言顶栏结构，新增导航入口安全。

## 2 · 主题令牌化架构

**原则：token 喂给 `background:` 简写** —— 因此 token 值既可以是纯色也可以是渐变，换肤无需改结构。

`:root` 在原 10 token 基础上扩充语义 token（默认值 = 现视觉，保证重构零视觉漂移）：

```
--app-bg        body 背景（纯色或渐变，默认 var(--bg)）
--panel-2       次级面：表头/按钮面/输入底      (#fafbfe)
--soft          中性软填充：标签/徽章/序号      (#eef0f7)
--accent-soft   强调软底 · hero 渐变起点        (#eef2ff)
--accent-soft-2 hero 渐变终点                  (#fdf4ff)
--ok-soft / --bad-soft / --warn-soft / --warn-ink   状态软底
--code-bg / --code-ink / --font-mono                代码块
--paper         关卡舞台纸面（内容层，皮肤预设不翻转）
--shadow-rgb    阴影基色（rgb 三元组，供 rgba() 组装）
--font-ui / --font-display                          界面/标题字体栈
```

换肤方式：`document.documentElement.dataset.skin = id`，CSS 侧 `:root[data-skin='…'] { … }` 整组覆盖 token。用户级覆盖（背景图/水印/字体）以 `--user-*` 变量内联在 `documentElement` 上，CSS 以 `var(--user-x, var(--skin-x))` 形式消费。

分层 z 序：`body 背景(token/渐变) < .user-bg(fixed, z:-1) < .watermark(fixed, z:-1, DOM 靠后) < .app 内容`。两层均 `pointer-events:none`，不拦截任何交互（功能不受影响的硬保证）。

## 3 · 本地自定义资源管道

- 偏好：`localStorage['skin.prefs.v1']`——`{ skinId, bg:{id,opacity,scope}, wm:{id,opacity,pos,fade}, font:{ui?,display?} }`，**只存元数据不存图片**。
- 资产：独立 Dexie 库 `skin-assets`（`src/skin/assets.ts`），表 `files`（图片 Blob，ULID 主键、≤1920px 压缩）与 `fonts`（`{name, data:ArrayBuffer}`）。启动时异步装载：blob → objectURL → `--user-bg-image/--wm-image`；fonts → `FontFace` → `document.fonts.add`。
- 图片上传统一画布压缩（长边 ≤1920，JPEG 0.85）；字体支持 woff2/woff/ttf/otf。
- 全部本地（localStorage + IndexedDB），**不经过云盘/账户体系**。

## 4 · 新页面布局

### 文档页 `#/docs`（参考 api-docs.deepseek.com/zh-cn）

- 三段式：左侧分组目录（含搜索框）+ 正文 + 底部上一篇/下一篇翻页器；≤720px 目录折叠为顶部横向滚动锚点条（沿用批次12 断点）。
- 内容为本项目真实用户文档（TSX 结构化数据，非运行时 markdown 管线）：开始（平台简介/快速上手/导航）、玩法（关卡类型/判定与进度）、创作（编辑器五视图/数据表/五线谱快捷键/节点图/LevelScript/flow）、参考（表达式函数/组件与事件/文档格式/快捷键）、扩展（AI 创作/账户与云盘/导入导出/FAQ）。
- 版式类全部走 token：`.docs-side/.docs-link/.docs-article/.docs-callout/.docs-code/.docs-table/.docs-pager`。

### 皮肤中心 `#/skins`

- 预设皮肤卡：CSS 迷你预览（底色/强调条/标题字样）+ 点击即换（`data-skin` + 持久化）。
- 自定义背景：作用范围（全局/仅首页）+ 换图/清除 + 透明度。
- 水印图：换图/清除 + 透明度 + 位置（平铺/居中/四角）+ 边缘渐隐。
- 字体：界面/标题两个槽位，可选「跟随皮肤 / 本机字体（带可用性检测）/ 已导入字体」；支持导入字体文件并管理删除。
- 页脚注明：背景图、水印、字体导入均仅存本机，不同步云端。

## 8 · 验证轮发现并修复的问题

1. **内容层对比度**（P0）：深色皮肤下舞台内硬编码浅底组件（重听按钮等）配了翻转后的浅色文字。修复：`.stage-canvas`/`.editor-canvas` 钉回浅色内容 token（内容层浅色岛），舞台视口铺 `--paper` 纸面底。
2. **存量 bug**：`.editor-canvas` 的 `background` 简写把颜色写在非末层，整条声明一直被浏览器丢弃（画布从未真正铺底/网格从未显现）。拆分为 `background-color` + `background-image`，恢复设计本意。
3. 表单控件（range/checkbox 等）增加 `accent-color: var(--accent)` 随主题。
4. `updatePrefs` 落盘剥离 `rt` 运行时字段（存储只存元数据）。
