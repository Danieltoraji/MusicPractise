## 1. R14 数据表行虚拟化（D1）✅

### 1.1 问题（docs/40 D1 / docs/43 §7）

- 数据表无行虚拟化：512 行 schema 上限下，一次渲染挂载全部行 → 每行 notes 单元格都挂 `StaffPreview`（VexFlow 迷你谱 effect 重绘）、每个单元格输入框/监听；大表打字、切 Tab、滚动明显卡顿；
- 此前 R8 已把 `CellEditor`/`StaffPreview` memo 化（减少无关重渲），但**挂载数量**仍随行数线性增长。

### 1.2 实现

| 文件 | 改动 |
|---|---|
| `src/editor/virtualRows.ts`（新） | `buildRowMetrics(rowCount, heightOf)`：按行高（含用户拖拽覆盖）构建前缀和偏移表，非法行高按 1px 兜底；`visibleRowRange(metrics, scrollTop, viewportHeight, overscan=4)`：二分定位首/末可视行、边界夹紧、超滚动/负值/零视口兜底 |
| `src/editor/TableGrid.tsx` | `.tgrid-wrap` 加 ref，监听 `scroll` + `ResizeObserver`（jsdom 无布局时 600px 兜底视口）；tbody 只渲染 `[start,end)` + 上下 `.tgrid-spacer` 占位行撑滚动高度；`slice` 后以 `start+offset` 还原**绝对行索引**（删行/行高拖拽/弹窗锚定数据行不受偏移影响） |
| `src/index.css` | `.tgrid-spacer`/`td`：占位行无边框/内边距，只负责高度 |
| `src/editor/virtualRows.test.ts`（新） | 纯函数 10 例：固定/可变/非法行高、空表、精确行边界、中部 overscan、超滚动/负值、零视口、512 行窗口 ≤25 行 |
| `src/editor/tableVirtual.test.tsx`（新） | 组件 4 例：200 行首屏 tbody < 40 行；滚到第 101 行（上占位 3456px、第 1 行卸载）；滚后编辑写回 `rows[100]`；滚到表尾（第 200 行、下占位消失） |

### 1.3 验证

- 定向：2 files / 14 tests 全绿；全量：**102 files / 929 tests 全绿**（39.71s）；`tsc` 0 错；`build` exit 0。
- 结构性证据：512 行满配在 600px 视口只挂载 ≤25 行（单测断言）；200 行首屏渲染 21 行；滚动到中部只挂载视口+overscan 行。
- 交互回归：行内编辑写回绝对行号、首/尾占位高度、删除/行高逻辑沿用原路径。

### 1.4 限制与后续

- 仅纵向虚拟化；列数上限 32（schema），横向不虚拟化可接受。
- overscan 固定 4；超快速滚动（跳转大距离）可能有短暂空白，后续可按速度自适应 overscan。
- 行高仍按行号键存（D3 遗留的稳定 rowId 改造未做）；虚拟化后该问题只影响可见行，风险不变。
- 若未来加「全选/批量复制」跨行操作，需要显式跨可视区选择模型（当前交互均为单行内编辑/弹窗）。
