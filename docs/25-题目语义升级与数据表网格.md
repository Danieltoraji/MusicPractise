# docs/25 · 「题目」语义升级：行指针变量化 + 模版视图移除 + 数据表网格

> 批次 3-7（2026-09-21）。背景：用户对 v3「视图 / 数据表 / 模版视图」的设计讨论——
> ① 数据表可视化不彻底（手写 JSON）；② 行指针应是变量（改变量即刷新视图，模版视图不再必要）；
> ③ 节点图区分「关卡」与「题目」（一题 = 一行）。用户确认改名走引擎级。

## 1. 设计裁决

### 1.1 行指针 = 变量（核心裁决）
- `v.__row` 从「只写的系统变量」升级为**响应式行指针**：节点图 `赋值 v.__row = N` 即跳转到
  **原始行号为 N** 的题目，触发完整行装载（停计时器 → 写指针 → 当前视图重放绑定 → onRow →
  派发 `question.loaded`）。
- 实现：`GraphEngine` assign 分支检测 `ROW_POINTER_VAR` 写入 → 宿主钩子 `rowPointerWrite` →
  `LevelSession.jumpToRow`。`loadRow` 内部**直写** `engine.vars.__row` 绕过钩子（防递归）。
- **语义（评审钉死）**：`v.__row` 读与写都是**原始行号**（shuffle/count 下 `jumpToRow` 用
  `order.indexOf` 反查 flow 位置）；行号不在本局（被 count 抽掉/越界/负数）→ 忽略；
  同行赋值 → no-op（防事件环）；结算后 → 忽略（终态）。
- lint：`__row` 视为系统级声明（免 undeclared-var）；graphOps 变量函数对 `__row`
  抛错（不可声明/改名/删除）；变量面板常驻说明行；assign 目标下拉收录（标注「题目行」）。

### 1.2 模版视图移除
- `level.next` → `question.next`：**纯推进**（末题仍自动结算），不再 setView 模版视图。
- 换行后**当前视图**内容自动刷新——机制本就存在：`loadRow` 对当前视图重放绑定 + 
  `question.loaded` 事件重放逻辑命令。模版视图是多余的第三条刷新通路。
- 单视图关卡行为完全不变；多视图关卡换行后停留在当前视图（设计意图）。
- `ViewDef.template` 字段删除；**schema 保留该属性（标注废弃）**——旧 v3 文档必须能过
  装载校验，进迁移器后由 `normalizeV3Content` 剥离（见 §3 P0 教训）。

### 1.3 关卡 vs 题目（引擎级改名）
| 旧 | 新 | 说明 |
|---|---|---|
| `level.questionLoaded` | `question.loaded` | 负载不变 `{index,total,row}`（row=原始行号） |
| `level.next` | `question.next` | 末题自动结算不变 |
| `level.started / level.finished / level.restart` | 不变 | 关卡级 |

- 事件面板分组改为「关卡 / 题目 / 视图 / 组件事件 / 内部事件」；节点库「关卡与题目」组。
- `question` 加入组件 id 保留字（schema `not anyOf`，与 level/views 同）。
- 脚本投影零特判（call 节点字符串拼接，改名自动生效）。

### 1.4 绑定面扩大（行驱动视图的广度）
- `label` 增加 `text` 绑定槽位：`$q.title` 即随行自动刷新，无需在 question.loaded 里重放
  `show` 命令。数字/布尔绑定值 String 收敛（与 props 初始口径一致）。
- 音色实验室改用绑定示范新范式（progress 因需 index/total 保留逻辑图）。
- 既有：choice.options / staff.music 不变。

### 1.5 数据表网格（零 JSON）
- TableEditor 抽出为 `TableGrid.tsx`：真 `<table>` 网格。列头=列名+显示名+类型+删除；
  行头=题号（即 v.__row 行号）+删除；列头右缘/行头下缘 pointer-capture 拖拽调宽高
  （**编辑器内存态**，不进文档 JSON；会话内保持）。
- 列类型 `columns[].type`：`text | number | boolean | notes | list | json`。
  单元格按类型渲染专用编辑器；**json 是高级兜底**（弹层 textarea），日常零 JSON。
  不合规数据（如 notes 列遇到字符串）不静默破坏 → 引导 JSON 弹层修正。
- 迁移器启发式 `inferColumnType`：全布尔→boolean；全数字→number；数组且元素含数字 midi→notes；
  字符串数组→list；对象/数组→json；否则 text。已设 type 不重推（幂等）。

## 2. 迁移器规范化（docs/25 语义层）
- `migrateDocToV3` 对 v1→v3 产物与**已存 v3 文档**统一执行 `normalizeV3Content`（幂等纯函数）：
  1. `normalizeLogic`：on 事件改名 + call `level.next→question.next`（导出，供只迁逻辑的
     管线如 migrate.test golden 对齐）；
  2. 剥离 `views[].template`；
  3. 列类型启发式补全。
- `compileLogicPatches` 产出的行门控子图直接生成 `on question.loaded`（门控 `v.__row == i` 不变）。
- schemaVersion 保持 3（规范化幂等，无需 bump）；schema 的 ViewDef.template 为兼容保留（废弃）。
- 内置样例按新管线重新生成（builtinEquivalence 的确定性断言强制）。

## 3. 评审结论与修复（P0/P1/P2）
- **P0**：schema `ViewDef` 删 template 后，旧 v3 用户文档在 `loadLevelDoc` 的 schema 校验
  直接失败（`additionalProperties: false`），规范化根本轮不到执行 → 游玩/导入全挂。
  **修复**：schema 保留 template（废弃标注）+ 迁移器剥离。教训：**删字段 ≠ 删 schema 属性——
  已存文档的兼容路径是 schema 放行 → 迁移器清洗**，先拦后洗等于拒载。
- **P1**：`v.__row` 读写语义不一致（读原始行号、写按 flow 位置）——shuffle 下「读出再写回」
  19/30 次跳错行。**修复**：统一原始行号语义 + 5 行随机不变式回归用例。
- **P1**：`question` 漏加组件保留字——id 叫 question 的组件会被伪实例吞命令。已加。
- **P2**：normalizeV3Content 对畸形 views 兜底 `?? []`；label 绑定数字/布尔 String 收敛；
  golden 补「v3 侧不得残留 level.next」断言（canon 折算只容忍 v1 侧）；
  删除无引用的 public/editor-config.json；docs/24 文案更新。

## 4. 边界备忘（记录在案，未改）
- assign `v.__row` 在处理器中段执行时，同链后续节点的 `q.*` 读的是**旧行**（scope.q 在
  handler 起点捕获；`v.*` 是活引用）。作者在链上先跳行再读 q 会拿到旧行——文档级注意点。
- `execQuery`（assign 右侧查询）只对 `level` 抛友好错误；`question` 落到「未知实例」。
- 列宽/行高不持久化；question.goto 命令被裁剪（assign v.__row 覆盖）；通用嵌套对象
  结构化编辑器出界（json 弹层兜底）。

## 5. 耦合点速查（未来改动先看这里）
- 行指针写入：`levelSession.loadRow`（唯一合法写入点）；钩子：`graphEngine assign 分支`。
- 模版视图残余：schema 废弃属性（勿删！）+ migrateDoc 剥离 + 测试夹具不得再写 template。
- 改名映射：`LEGACY_QUESTION_LOADED`（migrateDoc）→ 新旧文档兼容的唯一入口。
- 列类型：`schemas/v1/level.json` enum、`level.ts ColumnType`、`TableGrid COLUMN_TYPES/
  DEFAULT_COL_W`、`inferColumnType` 五处同步。
