## 2. LevelDocV4

```ts
export interface LevelDocV4 {
  schemaVersion: 4
  kind: 'level'
  id: string
  version: string
  meta: { title: string; [k: string]: Json }   // 沿用 v3 meta 形态（author/tags/description…）
  refs?: unknown[]
  content: LevelContentV4
}

export interface LevelContentV4 {
  shell: LevelShell
  /** 题型声明（数组顺序 = 自动题单的同 phase+order 平票排序） */
  types: QuestionTypeDef[]
  /** key = 题型 id；必须与 types 一一对应 */
  tables: Record<string, QuestionTable>
  /** 缺省 = 自动题单；存在 = 显式优先 */
  manifest?: ExplicitManifest
  run: RunConfig
  flow: FlowProgram
}
```

编译期/装载期不变量：
- `run` 可省略：JSON Schema 允许 content 缺 `run`，装载时 `normalizeLevelDocV4` 补默认 `{order:'manifest', count:null, seed:null, shuffleWithinPhase:true}`（运行时文档恒有 run）。
- `types[].id` 唯一；`tables` 键集合 == `types[].id` 集合；行 id 在题型内唯一（全局不强求）。
- `meta.title` 非空；`version` 为 semver 形态（沿用现有约束）。
- 未知字段：normalize 保留但 lint 警告（向前兼容），渲染/执行不读取。

## 3. 表现层：shell / surface / 组件 / 绑定

```ts
export interface LevelShell {
  views: ViewDef[]                 // {id,name?}，≥1；缺省视图 = 首个
  components: ComponentInstanceV4[]
  initialView?: string             // 缺省 views[0].id
}

export interface ComponentInstanceV4 {
  id: string                       // shell：全局唯一；surface：题型内唯一
  type: string                     // 组件契约类型（componentDef 注册表）
  name?: string
  visible?: boolean
  layout?: { x: number; y: number; w: number; h: number }  // 800×470 坐标系
  props?: Record<string, Json>
  view?: string                    // shell 必填且属 views；surface 禁止
  bindings?: Record<string, string> // slot（DATA_APPLY_COMMANDS 槽位）→ 只读表达式
}

export interface QuestionTypeDef {
  id: string
  name: string
  description?: string
  surface: { components: ComponentInstanceV4[] }   // 题型本地组件；运行时内部命名空间隔离
  behavior: BehaviorProgram
  state?: StateFieldDef[]          // q.state.* 初始 schema（每 (type,row) 一份，本局持久）
  typeState?: StateFieldDef[]      // t.* 初始 schema（每题型一份，本局持久）
  args?: ParamFieldDef[]           // ask 调用参数 schema（编辑器表单/lint 用）
}

export interface StateFieldDef { key: string; type: 'number' | 'boolean' | 'string' | 'json'; init: Json }
export interface ParamFieldDef { key: string; type: 'number' | 'boolean' | 'string' | 'json'; optional?: boolean; default?: Json }
```

### 3.1 渲染组合

- 舞台固定 800×470，单次 fit-scale；shell 层在下、surface 层在上，绝对定位同坐标系。
- shell 组件按当前视图过滤（`c.view ?? firstView`），跨题常驻（store 不重建）。
- surface 组件仅在题型调用期间挂载；调用结束**整帧卸载**（React key=callId），组件内部状态每次调用重置；`q.state`/`t` 不重置。
- 组件事件：shell 组件 → flow 的 `waitShell`（或忽略）；surface 组件 → 当前 behavior。题目执行期间 shell 事件被忽略并写调试日志（不 console）。
- 题面由题型 surface 自己显示（shell 绑定不能读 `q`）；进度由 runner 用 `session.progress` 渲染；结算条由 runner 用 `session.result` 渲染。

### 3.2 绑定（只读投影）

- 槽位 = `DATA_APPLY_COMMANDS[component.type]` 的键（label.text / choice.options / staff.music；v4.0 仅这三类组件支持绑定）。lint：不支持的 type/slot 报 `V4_BINDING_SLOT`。
- 求值时机：挂载时求值并合并进 `props` 生成初始 state；此后**运行态变化时**重新求值，值深比较变化才下发对应命令（`applyCommand(method, {[argKey]: value})`），不触发作者逻辑、不写作用域。
- 作用域：shell 绑定可用 `v`/`run`；surface 绑定可用 `q`（内容+`q.id`）/`q.state`/`t`/`args`/`v`/`run`。均只读。
- 求值失败：该槽跳过 + 运行日志（每组件槽位只记一次），不中断关卡。
- `TODO(spike)` W3.4 验证求值/命令时序；降级方案：只在挂载时求值一次（一次应用），并记录限制。

## 4. 数据层：题型实例表

```ts
export interface QuestionTable {
  columns: ColumnDef[]
  rows: QuestionRow[]
}
export interface ColumnDef { key: string; label?: string; type?: ColumnType }  // ColumnType 沿用 'text'|'number'|'boolean'|'notes'|'list'|'json'
export interface QuestionRow {
  id: string
  draft?: boolean      // 草稿/备用：不进入自动题单
  phase?: number       // 阶段，默认 1；整数 ≥1
  order?: number       // 阶段内顺序，默认 = 行下标
  [contentKey: string]: Json
}
```

- **q 作用域** = 当前行内容（只读）+ `q.id`（只读）；行元数据（id/draft/phase/order）不进入内容列。
- 保留字段：`id`、`draft`、`phase`、`order`、`state` 不得作为内容列 key；内容列 key 不得以 `__` 开头。
- 缺失单元格读取为 `null`；未知内容键 = 校验错误。
- 限额（`schemas/v4/level.json` 与 `schemaLimits` 一致）：每关题型 ≤ 12；每型行 ≤ 512；每型列 ≤ 32；全关行合计 ≤ 1024；explicit manifest 条目 ≤ 2048；surface 组件/型 ≤ 32；shell 组件 ≤ 64；views ≤ 16；单程序节点 ≤ 512、边 ≤ 1024；表达式源 ≤ 2000 字符。

## 5. 题单与牌堆

```ts
export interface ExplicitManifest { entries: ManifestEntry[] }
export interface ManifestEntry { type: string; row: string; args?: Json }  // args 为对象或 null

export interface RunConfig {
  order?: 'manifest' | 'shuffle'    // 默认 'manifest'
  count?: number | null             // 默认 null = 全部
  seed?: number | string | null     // 默认 null = 本局随机并记录
  shuffleWithinPhase?: boolean      // 默认 true
}

export interface DeckItem {
  type: string; row: string
  args?: Json
  slotIndex: number   // 牌堆内 0 起
  phase: number
  order: number
}
```

**自动题单**（无 `manifest`）：

```
for typeIndex, type of content.types:
  for rowIndex, row of tables[type.id].rows:
    if row.draft === true: continue
    entries.push({type,row, phase: row.phase ?? 1, order: row.order ?? rowIndex, typeIndex, rowIndex, args: undefined})
sort by (phase asc, order asc, typeIndex asc, rowIndex asc)
```

**显式题单**：严格按 `entries` 顺序；只执行列出项；`draft` 不影响（编辑器给警告）；phase/order 取行元数据（用于牌堆分组）。

**发牌**：

```
deck = manifestItems.slice()
if run.order === 'shuffle':
  if shuffleWithinPhase: 按 phase 分组（阶段顺序不变）、组内 Fisher–Yates
  else: 整体 Fisher–Yates
if run.count != null: deck = deck.slice(0, min(count, deck.length))
分配 slotIndex
```

- PRNG：`seed == null` 时用 `crypto`/`Math.random` 生成 uint32 并记录到 `run.seed`；否则 `hashSeed(seed)`（字符串 FNV-1a）→ **mulberry32**。同一 seed + 同一 manifest + 同一行集合 ⇒ 同一牌堆（调试/AI/重开复现）。
- 重开（`restart`）默认重新发牌（seed 为 null 时换新随机 seed；固定 seed 时复现）。
- 重复槽位：显式题单允许同一 (type,row) 多次（args 不同）；`q.state` 共享，调用局部/组件状态每次重置。
- 对 flow 暴露（只读 `run.*`）：`run.questions: DeckItem[]`、`run.total: number`、`run.seed: number`、`run.index: number`（已发起的 ask 次数）。

## 6. FlowProgram IR 与执行语义

```ts
export interface FlowProgram {
  logicVersion: 3
  kind: 'flow'
  nodes: FlowNode[]
  edges: GraphEdge[]
  vars?: StateFieldDef[]      // run 作用域 v.* 的声明与初值（editor/预设维护）
}
export interface GraphEdge { id: string; from: string; to: string; port?: 'true' | 'false' }
type NodeBase = { id: string; x?: number; y?: number }
type RValue = { expr: string } | { query: { target: string; method: string; arg?: string } }
interface QueryCallView { target: string; method: string; arg?: string }
```

节点（`FlowNode`）：

| kind | 字段 | 出端口 | 语义 |
| --- | --- | --- | --- |
| `start` | — | 单 | 唯一；无入边；从这里开始 |
| `assign` | `target: string`（`v.x`/`local.x`）, `value: RValue` | 单 | 求值写入；目标必须是已声明变量 |
| `call` | `target`（shell 组件 id 字面量）, `method`, `arg?: string`（表达式→对象） | 单 | 调 shell 组件命令（contract.commands 或 BASE_COMMANDS） |
| `setView` | `view: string`（字面量） | 单 | 切换 shell 视图（**docs/51 的补充**：v3 `views.goto` 的显式节点化） |
| `ask` | `target: string`（表达式）, `args?: string`（表达式→对象）, `resultVar: string` | 单 | 调用题型函数并挂起等待；结果写 `local.<resultVar>` |
| `foreach` | `items: string`（表达式→数组）, `itemVar: string`, `indexVar?: string` | true=body / false=done | 顺序遍历；每次迭代写入局部变量；体尾回边回到 foreach |
| `branch` | `cond: string` | true/false | 条件分支 |
| `loop` | `mode:'while'\|'repeat'`, `cond?`, `times?` | true=body / false=exit | while 每轮求值；repeat 首次进入捕获次数 |
| `wait` | `ms: string` | 单 | 休眠 [0, 600000] ms |
| `waitShell` | `event: string`（`<shellCompId>.<eventName>` 字面量） | 单 | 挂起等待 shell 组件事件（仅题目执行之外） |
| `finish` | `passed?: string`（表达式，缺省 `'true'`） | 单 | 记录结算（幂等），之后流程可继续 |
| `restart` | — | 无 | 终止当前 run 并重新开始（取消进行中调用） |
| `comment` | `text: string` | 无（不参与执行） | 注释/说明节点 |

执行规则：
- 单链执行：`start` 出发沿边前进；双出口节点按端口取边；出边缺失 = 该路径结束。
- 循环状态按 `frame.loopState[nodeId]`（同一节点不可递归进入；嵌套循环靠内层 done 清状态）。
- `ask` 生命周期见 §9；`waitShell` 等待期间事件投递规则：只有匹配事件唤醒流程，其余 shell 事件忽略。
- `finish` 之后仅允许：`call`(shell) / `setView` / `waitShell` / `wait` / `restart` / `comment`；其他节点运行时报错并终止流程（lint 同时报 `V4_ASK_AFTER_FINISH` 等）。
- 流程自然结束且未 `finish`：运行日志 warning + lint warning（`V4_UNSETTLED_FLOW`），不产生结算。
- 预算：每个 run 累计节点步数 ≤ 10000；超限终止并报 `V4_BUDGET`。

## 7. BehaviorProgram IR 与执行语义

```ts
export interface BehaviorProgram {
  logicVersion: 3
  kind: 'behavior'
  nodes: BehaviorNode[]
  edges: GraphEdge[]
  locals?: StateFieldDef[]    // 每次调用初始化的 local.*（覆盖式初值）
}
```

节点（`BehaviorNode`）：

| kind | 字段 | 出端口 | 语义 |
| --- | --- | --- | --- |
| `on` | `event: string` | 单 | 事件入口，无入边。允许三类：`start`（必须恰有一个）、`internal.<name>`（emit 内部事件）、`<surfaceCompId>.<eventName>`（组件事件/计时器 tick） |
| `return` | `result: string`（表达式→QuestionResult） | 无 | 结束本次调用；首个生效；之后事件丢弃、任务取消 |
| `assign` | `target`（`q.state.x`/`t.x`/`local.x`）, `value: RValue` | 单 | 写权限见 §8；query 只能查本题 surface 组件 |
| `call` | `target`（surface 本地组件 id）, `method`, `arg?` | 单 | 命令只能作用于本题 surface 组件 |
| `emit` | `event: 'internal.<name>'`, `payload?: Record<string, string>`（值表达式） | 单 | 派发题型内部事件（排队，不中断当前链） |
| `branch` / `loop` / `wait` / `comment` | 同 §6（字段语义一致，作用域不同） | 同 §6 | — |

执行规则：
- 调用开始派发 `start` 事件：为该 `on start` 创建任务执行其链。
- 事件模型：`dispatch(event,payload)` 按程序顺序为每个匹配 `on` 创建独立异步任务；**任务内顺序执行，任务间仅在 await 点（wait）交错**；事件队列 FIFO；`emit` 入队后当前任务继续。语义以「不中断当前链」为准，不承诺未定义交错顺序；测试用注入计时器/假时钟确定化。
- `return` 一旦执行：本次调用立即结束（其它任务在下一个节点/await 边界前取消），返回值归一化后交给 flow，surface 卸载、本帧计时器停止、后续事件丢弃。
- 错误：任务内节点错误（表达式/权限/命令/预算）→ 调用以 `{status:'error',message}` 返回并写运行日志；不再执行该任务后续节点。
- 取消：restart/exit/watchdog → 帧作废，不产生返回值；所有任务/计时器清理。
- 预算：单次调用累计节点步数 ≤ 2000、并发任务 ≤ 64、事件 ≤ 256；超限 → error 结果。watchdog 默认 120000ms（host 可覆盖）→ `status:'timeout'`。
- 组件命令/查询只允许本题 surface 组件；不能访问 shell、不能 `ask`/`finish`/`restart`/`setView`；不能写 `v.*`。

## 8. 作用域与表达式

### 8.1 作用域矩阵

| 名字空间 | 生命周期 | 归属 | flow | behavior | UI 绑定 |
| --- | --- | --- | --- | --- | --- |
| `v.*` | run | flow | RW（仅 `flow.vars` 声明项） | RO | RO |
| `t.*` | run（按题型） | behavior | RO | RW（仅声明项） | RO |
| `q.*` | 文档 | 作者 | RO（`contentOf` 查询跨题） | RO（当前行内容） | RO（surface） |
| `q.state.*` | run（按 (type,row)） | behavior | RO（`stateOf` 查询） | RW（仅 `type.state` 声明项） | RO |
| `local.*` | 一次调用/一次 run（flow） | 当前帧 | RW（声明或隐式结果变量） | RW | — |
| `args.*` | 一次 ask 调用 | 调用方 | — | RO | RO（surface） |
| `run.*` | run | 运行时 | RO | RO | RO |
| `event.*` | 一次事件处理 | 运行时 | — | RO（handler 链） | — |

- **显式命名空间**，不做同名覆盖；表达式源码禁止 `$` 前缀；未允许的根 → lint/运行错误。
- `run` 结构：`{questions: DeckItem[], total: number, seed: number, index: number}`（只读）。
- flow 可用内置函数 `stateOf(type, row, field)`（读该题 `q.state.<field>`，缺失返回 `null`）、`contentOf(type, row, field)`（读行内容列，缺失返回 `null`）；behavior/绑定层不可用（运行时 ctx 不注入钩子）。**实现修订（Round 2）**：原设计为返回整个对象，但表达式语法不支持「函数返回值再取成员」，故改为三参数按字段读取；需要整对象语义时后续再评估语法扩展。其余函数沿用 v3 白名单 21 个（`exprFunctionNames` 不暴露 v4 专用函数）。
- 写入目标（assign/resultVar/itemVar）：
  - flow：`v.<name>`、`local.<name>`（`ask.resultVar`、`foreach.itemVar/indexVar` 为隐式局部）。
  - behavior：`q.state.<key>`、`t.<key>`、`local.<name>`。
- 声明校验：写未声明变量 → lint `V4_WRITE_DENIED`；运行期同样拒绝（防 lint 关闭时脏写）。
- `q.state` / `t` 初始化：run 开始时按 schema 深拷贝初始化所有题型所有行；`restart` 重新初始化。不跨局持久。

### 8.2 表达式求值

- 沿用 v3 沙箱（解析器/白名单/步数预算/严格相等/原型防护），扩展为**多根环境** `Record<root, Json>`；v4 编译缓存按「源码 + 根集合」。
- 核心 `src/engine/expr.ts` 增量（v3 行为不变）：`ExprEnv`、`compileEnvExpr`/`evalEnvExpr`、`ExprContext.questionState/questionContent` 钩子、`stateOf`/`contentOf`（v4 专用，默认不进入 `exprFunctionNames`）；v4 包装层 `src/engine/v4/expr.ts` 提供根集合常量、AST 根/函数名提取、静态校验、路径读写与写权限校验。
- 静态校验：解析 AST 提取根标识符 → 对照层允许根；可静态判定的路径（`q.<column>`、`q.state.<key>`、`t.<key>`、`args.<key>`）对照 schema 校验；字面量组件/视图/题型引用同样校验。
- 赋值路径：`setPath(env, 'q.state.answered', value)`；只允许两层/三层路径（根 + 1~2 段）；根段不可为 `__proto__` 等。
- 空字符串表达式：可选字段按「未提供」处理，必填字段报错。

## 9. 调用协议（ask）与 QuestionResult

```ts
export type QuestionStatus = 'answered' | 'skipped' | 'timeout' | 'aborted' | 'error'
export interface QuestionResult {
  status?: QuestionStatus   // 缺省 'answered'
  correct?: boolean
  scoreDelta?: number       // 有限数字；不自动应用
  payload?: Json
  message?: string
}
```

`ask` 执行：
1. 求值 `target`：DeckItem 或 `{type,row,args?}`；解析类型/表/行；失败 → 运行日志错误并把 `{status:'error',message}` 写入结果变量（flow 可分支）。
2. 合并参数：`target.args`（底层）← `args` 表达式（覆盖）；必须是对象/`null`；按 `type.args` 补默认值并校验。
3. 建帧：callId 自增；内容只读引用行内容（深拷贝快照）；实例态引用该 (type,row) 的 `q.state`；题型态引用 `t`；args；local 按 behavior.locals 初始化。
4. 挂载 surface（绑定初始应用）→ 派发 `start` → 等待返回/取消/watchdog。
5. 归一化 `QuestionResult`：未知字段忽略；非法 status/scoreDelta → `status:'error'`；缺省 status='answered'。
6. 清理本帧计时器、卸载 surface；`local[resultVar] = result`；flow 继续。
7. `scoreDelta` 不自动应用；由 flow 预设写 `v.score`（约定：`v.score` 为数字账本，finish 读取）。

取消/异常：
- restart / 关卡退出 / 宿主 dispose → 帧作废，不产生返回值。
- behavior 抛错 → `status:'error'`，message 可读。
- watchdog 超时 → `status:'timeout'`；flow 可正常处理。
- 同一实例多次 ask：`q.state` 持久；组件内部状态/局部变量重置。

`V4Session` 公开 API（冻结）：

```ts
class V4Session {
  constructor(doc: LevelDocV4, host: V4SessionHost)
  readonly shellStore: ComponentStore
  getSurfaceStore(): ComponentStore | null
  getSnapshot(): V4Snapshot
  subscribe(listener: () => void): () => void
  start(): void                    // 幂等：未 started 时执行启动序列
  restart(): void                  // 取消 → 重置 → 重新发牌 → 重新 start
  dispose(): void                  // 取消帧/计时器/清订阅（不主动停全局音频）

  dispatchSurfaceEvent(localId: string, event: string, payload?: Json): void

  setTimersPaused(paused: boolean): void
}
```

启动序列：校验由装载管线负责 → 初始化 `v`（flow.vars 初值）→ 初始化 `t`/`q.state`（全表）→ 生成题单/牌堆 → shell store 初始化（全部 shell 组件；渲染按当前视图过滤）→ 派发 flow `start`。
`finish`：记录 `{score: v.score 数字或 0, passed}`（幂等，首个生效）→ `host.onFinished` → snapshot.result。
`restart`：flow 节点与 runner 重玩按钮共用。
运行日志：session 保留最近 200 条，`onRunEvent` 实时回传；runner 侧追加 `runlog:<levelId>`（沿用 v3 存储键）。

## 13. 编辑器模型（v4）

### 13.1 路由与加载

- `EditorPage`（路由壳）按 `loadLevelDoc` 后的 `schemaVersion` 分派：4 → `EditorPageV4`；过渡期 3 → 旧编辑器；W9 后只留 v4。
- 保存：`loadLevelDoc` 预检 → `bumpVersion` → `putResource` → 更新 clean 基线；内置关另存副本语义沿用 v3（新 id、标题加「（副本）」、历史/会话状态迁移）。
- 撤销/重做沿用 `src/editor/history.ts`（cap 50、cleanDocRef 判脏、同 tag 合并）。

### 13.3 Tab 信息架构

Tab（`data-testid=editor-tab-*`）：`content` 内容 / `flow` 流程 / `types` 题型 / `shell` 舞台 / `preview` 预览 / `json` JSON。

- **内容**：子页 `tables`（题型选择 + 实例表：列编辑、行增删重排、draft/phase/order、单元格弹窗）、`manifest`（自动题单只读预览 + 显式题单编辑 + 草稿引用警告 + run 配置与牌堆预览）。
- **流程**：Flow main 图工作台（图/伪代码切换、调色板、检查器、变量面板、预设画廊、lint 面板）。
- **题型**：题型列表 + 子页 表现（surface 组件列表/布局/初始 props/绑定）、行为（Behavior 图工作台，同构图编辑）、状态参数（state/typeState/args schema）。
- **舞台**：shell 视图管理 + 组件画布（拖放/缩放/属性/绑定）+ 预览。
- **预览**：v4 游玩画面 + 调试面板（调用栈/作用域/牌单/日志/每题结果），运行归属遵守 docs/40 §12.4。
- **JSON**：层选择（整关卡 / shell / types / tables / manifest / flow / behavior:<typeId>）+ 草稿陈旧门 + 应用走 `loadLevelDoc`。
- 题目执行期间禁止结构编辑（运行态），与现有 debug 归属纪律一致。

### 13.4 图工作台（GraphWorkbench）

- 受控单基线 `apply(fn)`（同 task 连续编辑不丢前一笔）；React Flow 12；节点卡/端口/连线规则按 §6/§7；双击/右键调色板；删除键；撤销走 docState tag。
- 检查器按层分组作用域（flow：`v/local/run`；behavior：`q/q.state/t/args/local/v/run/event`）；表达式实时 `checkExprText` + 根/路径校验。
- 主题：沿用 `--ge-*`（`.graph-editor.ge-dark` 双主题 fallback）与 `--ui-*`；不新增裸色；`<Background>` 等 React Flow 颜色传 `var(--ui-*)`。
- 锚点：`graph-card-<id>`、`palette-item-*`、`graph-dock-*`、`v4-graph-*` 等；G3 契约同步。

### 13.5 伪代码投影（v4 script）

Flow：
```
main {
  v.score = 0
  foreach slot in run.questions {
    ask slot -> result
    if result.scoreDelta != null { v.score = v.score + result.scoreDelta }
  }
  finish passed: v.score >= 60
}
```
Behavior：
```
on start {
  call sound.play({notes: q.notes})
}
on choice.chosen {
  if event.payload.index == q.answerIndex {
    q.state.answered = true
    return { status: 'answered', correct: true, scoreDelta: q.scoring }
  }
}
```
要求：`generateXScript` / `parseXScript` 往返恒等（注释/顺序稳定）；二次编辑用锚点合并（按语句特征配对，保留节点 id/x/y，保证 id 唯一、无悬空边/自环），合并后跑 lint。

## 14. 预设与零代码模板

```ts
export interface PresetDef {
  id: string
  name: string
  description: string
```

- 预设 = **普通节点组 + comment**（印章式），插入后作者可改；不做运行时隐藏策略；不写 `preset` 元数据到节点（v4.0 不支持「重新应用」，重新插入即可）。
- 内置目录（v4.0 至少）：
  - flow：`sequence-grade-settle`（顺序遍历+应用 scoreDelta+v.row+finish）、`retry-n`（答错重试 N 次）、`unlock-branch`（按 score/stateOf 分支）、`settle-then-replay`（finish→setView→waitShell→restart）。
  - behavior：`first-correct-once`（首次答对只计一次）、`every-correct`、`wrong-retry`、`manual-next`/`auto-next`、`timed-return`、`feedback-hint`。
- 预设必须有单测：展开节点过 schema+lint（连接后 0 错）；参数生效。
- 零代码模板：`blank` / `listen-choice` / `rhythm-tap` / `tutorial`，返回完整 `LevelDocV4`（类型/表/题单/流程/shell/预设节点），必须通过 schema+lint+无头通关 smoke。
