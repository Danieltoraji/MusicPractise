# 音乐练习 UGC 平台 · 技术预研报告

> 状态：v0.1（预研） · 日期：2026-09-16
> 配套文档：[02-数据结构设计.md](./02-数据结构设计.md) · Schema：`schemas/` · 原型：`src/`

## 1. 项目概述

纯前端 Web 应用，内容层级为 **系列 → 专题 → 关卡 → 题目**，所有层级支持 UGC。
关卡界面由**组件**拼装（音乐类：五线谱渲染器、发声器、指法显示器、鼓点显示器、校音器；交互类：文本、按钮、滑块、输入框、选择器等），组件可设为隐形；组件间关系与题目判据通过**统一接口**由逻辑系统（节点图 / 简易代码）描述。

纯前端约束下，UGC 的形态是**自包含 JSON 文档**：本地创作、本地存储、文件导入导出分发；数据结构按"未来可上后端"设计，不做任何只有本地才能表达的结构。

## 2. 总体架构

```
┌─────────────────────────────────────────────────────┐
│ 编辑器层（后续阶段）                                  │
│  关卡画布拖放 / 属性检查器 / React Flow 节点图 / 试运行  │
├─────────────────────────────────────────────────────┤
│ 运行时层（POC 范围）                                  │
│  关卡运行器：装载关卡 JSON → 实例化组件 → 驱动逻辑引擎   │
│  逻辑引擎：事件总线 + ECA 规则 + 安全表达式 + 变量存储   │
├─────────────────────────────────────────────────────┤
│ 组件层（统一契约 events / commands / state）           │
│  music: staff · sound · fingering · drums · tuner     │
│  ui:    label · button · slider · input · choice      │
│  hidden: timer · counter · 变量节点（隐形组件）         │
├─────────────────────────────────────────────────────┤
│ 内容层                                                │
│  资源信封：series / topic / level / instrument / asset │
│  （自包含 JSON + 版本 + 依赖清单，Ajv 校验）            │
├─────────────────────────────────────────────────────┤
│ 平台层：IndexedDB(Dexie) · 文件导入导出 · 进度存档      │
└─────────────────────────────────────────────────────┘
```

核心思想：**节点图和简易代码只是同一逻辑运行时的不同"编辑前端"**。运行时语义只有一种——事件驱动的 ECA（事件→条件→动作）规则 + 安全表达式。v1 用表单/JSON 编辑规则，v2 用 React Flow 把规则渲染成节点图（可视化编辑、编译回同一 LogicProgram），v3 增加 QuickJS 脚本节点覆盖长尾需求。

## 3. 技术选型对比

### 3.1 框架与构建：React 19 + TypeScript + Vite ✅（已确认）

React 生态最大，节点图编辑器 React Flow 原生支持；VexFlow / tonal / smplr 均有一手集成示例。Svelte Flow、Vue Flow 存在但生态较小。

### 3.2 乐谱渲染：VexFlow 5 ✅

| 库 | 定位 | 结论 |
|---|---|---|
| **VexFlow 5** | 底层刻绘引擎，TS 编写，输出 SVG/Canvas，程序化 API | ✅ **主选**。关卡题目是数据驱动的小节级渲染，需要"渲染任意音符组 + 点击/高亮单个音符"的细粒度控制，只有 VexFlow 提供这个层级 |
| OpenSheetMusicDisplay | 渲染完整 MusicXML（底层即 VexFlow） | 备用导入通道：用户从 MuseScore 等导出 MusicXML 导入题目谱面 |
| abcjs | 渲染 ABC 文本 + 自带播放 | 备用快速输入通道：ABC 文本适合创作者手写，可作 v2 的输入法之一 |

要点：VexFlow 本身不含交互，需自行封装「音符命中区域 → 点击事件」「按 midi 高亮音符头」。每个音符的 SVG 根元素可从 `note.attrs.el` 取得，直接挂 click 监听即可（POC 已验证该路径）。

### 3.3 乐理计算：tonal ✅

tonal 6.x：纯函数、TS、模块化（Note/Interval/Chord/Scale/Key），只处理抽象不碰音频，与渲染、发声解耦。表达式语言的内置函数（`midiToName` 等）直接基于它实现。

### 3.4 发声：原生 WebAudio 引擎 + smplr ✅

| 方案 | 结论 |
|---|---|
| **smplr 1.0** | ✅ 主选：采样钢琴 / GM 音色，零配置加载，作者即 soundfont-player 作者的现代化继任 |
| 原生 WebAudio | 引擎底座： oscillator 合成（提示音）、鼓组合成、精确调度 |
| Tone.js | 备选：Transport/效果器/合成器全家桶，但体积与抽象层级偏重；POC 未用，节奏调度自行实现 lookahead 模式即可 |

关键约束：**一切以 `AudioContext.currentTime` 为唯一时间基准**（视觉节拍高亮、节奏判定网格、发声调度都换算到它），杜绝音画漂移。iOS/Safari 需在首次用户手势中 `resume()` AudioContext。

### 3.5 校音（频率计）：pitchy ✅

| 方案 | 结论 |
|---|---|
| **pitchy 4.x**（McLeod Pitch Method） | ✅ 主选：专为此场景设计，`PitchDetector.forFloat32Array(bufSize)` 一次一帧，返回 `[pitch, clarity]` |
| pitchfinder（YIN/AMDF/自相关） | 备选：算法可插拔，留作低音域不稳定时替换 |
| ml5.js / CREPE（ML） | 不选：模型重、依赖大，预研阶段不值得 |

生产路径：`getUserMedia` → AudioWorklet 采集环形缓冲 → 主线程/Worker 里跑检测（约 10Hz 节流）→ 发 `{freq, midi, cents, clarity}` 事件流。POC 用 `AnalyserNode.getFloatTimeDomainData` 简化（同源算法，不影响结论）。

### 3.6 节点图编辑器（二期）：@xyflow/react ✅

| 库 | 结论 |
|---|---|
| **React Flow（xyflow）12** | ✅ 主选：MIT、节点即 React 组件、文档生态最活跃 |
| Rete.js v2 | 备选：框架无关、自带 dataflow 引擎，若未来引擎语义要对外复用再看 |
| LiteGraph.js | 不选：canvas 自绘，与 React UI 融合差 |

注意：节点图是 LogicProgram 的**视图**而非另一种运行时，避免两套语义漂移。

### 3.7 逻辑与安全：自研表达式 + ECA，三期上 QuickJS

- **表达式语言自研**（约 200 行 Pratt 解析器）：无赋值、无循环、成员访问只允许作用域根（`event` / `q`(题目数据) / `v`(变量)）的纯数据路径；函数白名单；**步数预算**（求值节点计数超限即抛错）。expr-eval 2.x 可用但不支持成员访问，包装成本反高于自研；JSONLogic 表达能力弱（无函数）。
- **脚本节点（v3）**：quickjs-emscripten（QuickJS 编译为 WASM）：无 DOM/fetch/宿主全局，支持 CPU 中断与内存上限，宿主通过受控桥接暴露 `emit/get/set`。约 1MB，按需懒加载。
- 规则解释器本身有事件级步数预算，防UGC 关卡死循环（如规则 A 触发事件再触发规则 A）。

### 3.8 存储与分发

- **Dexie**（IndexedDB）：资源库（草稿/已发布）+ 练习进度存档。
- **文件导入导出**：关卡=单个 `.json`；含资产（音频/图片）时用 fflate 打 `.mpbranch` 包；导入时 Ajv 校验 + refs 闭环检查 + 版本冲突策略。
- URL 分享（可选，二期）：lz-string 压缩进 hash，仅适合 <10KB 的小关卡。

## 4. 关键设计决策（详见 02 文档）

1. **统一资源信封**：一切皆文档（series/topic/level/instrument/asset），`id + version + meta + refs + content`。
2. **关卡 = 组件实例 + 逻辑程序 + 题目列表 + 流程配置**；**题目=纯数据**，组件经 `bindings`（`"$q.xxx"`）随题注入——关卡逻辑是模板，一模板出多题。
3. **组件统一契约**：`events`（出）/ `commands`（入）/ `state`（可读状态）/ `propsSchema`；任何组件可 `visible:false`。
4. **乐器档案也是 UGC 资源**：指法显示器=渲染 instrument 文档 + 高亮命令，天然支持钢琴/吉他/自定义乐器。
5. 音乐专项：校音以节流事件流判 `|cents|<容差` 持续 N ms；节奏判定统一 AudioContext 时钟，内置 `rhythmMatch(taps, grid, toleranceMs)` 纯函数 + 输入延迟校准。

## 5. 风险清单与对策

| # | 风险 | 等级 | 对策 |
|---|---|---|---|
| 1 | VexFlow API 底层，封装（命中/高亮/布局）成本 | 中 | 做 `MusicDoc → 渲染` 受控映射层，组件内消化复杂度；POC 已打通点击事件 |
| 2 | 音画时钟漂移（视觉节拍 vs 音频节拍） | 高 | 唯一时间基准 `AudioContext.currentTime`；视觉用 requestAnimationFrame 读取它，禁止双时钟 |
| 3 | 节奏判定的人手延迟（50–150ms 因人而异） | 高 | 判定容差可配 + 用户自校准流程（tap 节拍器测偏移） |
| 4 | 浏览器自动播放策略 / iOS 解锁 | 中 | 首个用户手势统一解锁 AudioContext；入口按钮常在 |
| 5 | UGC 逻辑死循环/超载 | 中 | 表达式无循环 + 步数预算；规则级传播预算；v3 沙箱兜底 |
| 6 | UGC 质量参差（坏谱面、无解题目） | 中 | Schema 校验 + 逻辑 lint（悬空引用/环检测）+ 试运行强制 |
| 7 | smplr 音色首次加载慢（网络拉取采样） | 低 | 懒加载 + 加载态提示；可选本地缓存（IndexedDB/Cache API） |
| 8 | quickjs 体积（~1MB） | 低 | v3 才引入，动态 import |

## 6. 阶段路线图

- **阶段 0（预研）**：✅ 已完成，验证记录见 §8
- **阶段 1A（表达力优先，当前）**：序列播放（chord/seq 双模式）、序列作答（表达式数组/下标/append/join 等）、timer 组件（隐形）、slider/input 组件、fingering 组件最小版；新增旋律听写/限时反应/音名拼写示例关卡
- **阶段 1B（M1 资源库与分发）**：Dexie 资源库（草稿/发布/版本冲突）、统一装载管线（Ajv+lint+降级+ErrorBoundary）、导入导出（JSON/zip + refs 闭包）、进度存档、系列/专题浏览页
- **阶段 1C（M2 编辑器 MVP）**：关卡画布拖放、属性检查器（propsSchema 驱动）、规则编辑器（ContractDoc 单一来源枚举事件/命令）、题目编辑、JSON 双向视图、内嵌试运行
- **阶段 2**：React Flow 节点图编辑器（LogicProgram 视图）、鼓点显示器正式组件、MusicXML/ABC 导入
- **阶段 3**：QuickJS 脚本节点、URL 分享、（可选）轻后端社区分发

> **更正（2026-09-17）**：上表"发声"一行当时仅验证了 CDN 可达性与判定链路，**声音可闻性未经真人试听**。独立评审随后发现 P0：velocity 曾按 0..1 语义传参而 smplr 为 0-127 MIDI 尺度，导致钢琴静音——已修复（vel 改为 0..127），**待人工试听确认**。教训：音频类验证必须包含真人可闻性检查。

实测中发现并修正的两个库行为（已写进代码注释）：

1. **VexFlow 5 不再暴露 `note.attrs.el`**（protected）：改为用 `svg > g.vf-stavenote` 的 DOM 顺序与 `notes[]` 对齐来挂点击/高亮（v1 只支持单声部，约束已注明）。
2. **smplr 1.0 API 变更**：钢琴类为 `SplendidGrandPiano`，`new X(ctx)` 之外推荐直接函数调用；加载用 `.ready` Promise 属性（`load` 已弃用）；`start({note, velocity, time, duration})` 不变。

其余记录：生产构建单 bundle 约 1.4MB（gzip 792KB，VexFlow+smplr+React），阶段 1 需按路由做代码分割（dynamic import）。POC 界面用原生 CSS 保持轻量，生产栈的 Tailwind 在编辑器阶段引入。
