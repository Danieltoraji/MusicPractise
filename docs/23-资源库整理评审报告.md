# 23 · 资源库整理评审报告（文件夹树 + 直接编辑）

> 批次目标（用户指令）：整理资源库页面；让用户直接编辑关卡而非必须编辑副本；让系列可以作为文件夹打开。自主迭代不提问。
> 实现提交 120632f；评审修复提交 10e7582。317/317 测试全绿、tsc/build 干净。

## 1. 设计

- **系列 = 文件夹**：资源库从平铺表格改为可展开树——`📚 系列 ▸ 📂 专题 ▸ 🎯 关卡`。点标题或箭头展开/收起；系列/专题行显示子项计数；未被任何容器引用的资源（独立关卡/专题/乐器）归入「未整理」分隔区。搜索按标题过滤：命中文件夹保留整棵子树、命中叶子保留祖先路径，搜索态强制全展开。
- **直接编辑**：关卡行「编辑副本」改为「编辑」直达 `#/edit/{id}`。内置示例的约束保留在保存侧——`builtIn` 记录每次启动会被种子重写，覆盖保存会丢用户成果，因此**保存时自动另存为用户副本**（新 id、标题追加「（副本）」且去重、版本归零），编辑器无感切换到副本继续编辑；「试运行」也跳副本。数据安全与零摩擦兼得。
- 纯函数 `buildLibraryTree` / `filterTree` 落在 `src/library/browse.ts`（确定性 + 单测）：引用缺失的子 id 跳过；同一关卡被多个容器引用只归入先出现者；系列内专题的关卡同样标记已整理。

## 3. 评审结论（subagent 独立评审）

**结论：无 P0；P1×2 已修复后合并**（修复提交 10e7582，修复后 317/317 全绿）。评审以探针实测确认：内置另存链路无竞态（副本 putResource 完成后才切 hash，`builtIn=0` 使副本永不被种子覆盖）、树归属不变量成立（多系列共享专题各含一份、关卡不重复出现在未整理区）、搜索语义与 VS Code 惯例一致。

**P1（已修）**：
- P1-1 `buildLibraryTree` 无环检测——「专题 levelIds 含自己/两专题互指」是 schema 合法文档，可经导入入库，递归栈溢出导致资源库整页白屏（且删除入口就在该页，毒数据无法自救）→ `childRecords` 加深度上限（树语义 3 层：系列0→专题1→关卡2），循环截断为有限行
- P1-2 行操作 `display:none` 仅 hover 显隐——触屏设备「编辑/导出/删除」完全不可达 → `@media (hover: none)` 常显

**P2（全部处置）**：save 显式同步 `dirtyRef.current=false`（不再依赖 React 调度先于 hashchange 的时序假设）；内置另存提示经 sessionStorage 跨重挂载传达（原 setSavedTip 在 hash 跳转重挂载前即销毁、用户永远看不到）；save 防重入（快速双击不再产生双副本）；重复子引用去重（React key 冲突 + 计数虚高）；回归测试补齐（循环截断/重复引用/大小写过滤/partitionLevels 存活代码）。

**P2 记录在案**：搜索态点「收起」会悄悄改 expanded、清空关键词后节点意外展开（轻微 UX）；`.lib-badge` 10.5px 字号偏小（对比度过 AA）。
