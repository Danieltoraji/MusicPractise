- `src/engine/expr.ts` 增量（v3 行为不变）：`ExprEnv` 多根环境、`compileEnvExpr`/`evalEnvExpr`、`ExprContext.questionState/questionContent` 钩子、`stateOf`/`contentOf`（v4 专用，不进 `exprFunctionNames`）。
- `src/engine/v4/expr.ts`：四层根集合常量（flow/behavior/shell-binding/surface-binding）、AST 根与函数名提取、编译缓存、`checkV4Expr` 静态校验、`parsePath`/`readEnvPath`/`writeEnvPath`、`validateWriteTarget`（flow: v/local；behavior: q.state/t/local，声明校验）。
- 测试：`src/engine/v4/{model,manifest,expr}.test.ts` 共 48 项。

**验证证据**
- `npx vitest run src/engine/v4` = 3 文件 / 48 测试全绿；`npx tsc --noEmit` exit 0。
- 全量回归 `npm test` = **117 文件 / 1067 测试全绿（40.87s）**（原 1019 + 新增 48），v3 不受影响。
- 关键行为测试：normalize 幂等/不污染入参、自动题单排序与 draft 排除、显式题单悬空引用报错、seed 复现与阶段内洗牌、写入权限矩阵（flow 不得写 q.state、behavior 不得写 v）、v4 专用函数按层放行。

**偏差与决策**
- `stateOf/contentOf` 从「返回整个对象」修订为 **三参按字段读取** `stateOf(type,row,field)`：v4 表达式语法不支持「函数返回值再取成员」，否则作者无法访问字段；docs/53 §8.1 已回填修订说明。
- behavior 的 `event` 根保留在根集合中，由运行时在 handler 链注入；静态校验按层给集合，运行期再校验。
- 写入路径中间对象必须已初始化（会话按声明/vars/locals 预建），不在写时隐式创建，避免脏状态。

**下一步**

**产出**
- `schemas/v4/level.json`：LevelDocV4 JSON Schema（$id 独立于 v1；$defs 覆盖 shell/view/component/type/surface/state/table/column/row/manifest/run/flow/behavior/node/edge；限额与 id 形态；flow/behavior 节点按 kind 枚举、节点特定字段留给结构校验）。
- `src/engine/v4/validate.ts`：结构/引用校验（docs/53 §12 error 层）——id 唯一性、保留字/保留键、types↔tables 一一对应、列/行/状态字段校验、题单引用与草稿/重复警告、绑定槽位与表达式根、图结构（start/on start 数量、入边/终止节点、悬空/自环/端口协议、节点必填字段、组件/视图引用）、flow.vars/behavior.locals、全关行数与题型数上限；输出 `{errors,warnings}`（带 typeId/rowId/nodeId/path 定位）。
- `src/library/validate.ts` 改造：注册 v4 schema；`validateEnvelope` 按 `schemaVersion` 分派 v1/v3/v4 校验器；v4 错误位置中文化（题型/行/列/shell 组件/题单/流程节点等）；新增 `loadLevelDocV4`（schema → normalize → validateLevelDocV4，过渡期与 `loadLevelDoc` 并存）；`loadLevelDoc` 不受支持版本提示指向 v4 入口。

**验证证据**
- `npx vitest run src/engine/v4 src/test/v4` = **5 文件 / 74 测试全绿**。
- `npx tsc --noEmit` exit 0。
- 全量回归 `npm test` = **119 文件 / 1093 测试全绿（41.05s）**（Round 2 后 1067 + 新增 26），v3 零回归。

**偏差与决策**
- `run` 在 v4 schema 中可省略（normalize 补默认），便于手写文档/模板；docs/53 §2 已回填。
- 新增 `V4_NODE` 错误码（未知节点类型/必填字段缺失/引用组件或视图不存在），docs/53 §12 已补行。
- validate 与 lint 分工冻结：**validate = 结构/引用/图完整性**（装载拦截 errors + 可打开 warnings）；**lint = 表达式根/写权限/可达性/ask-after-finish/预设半成品等语义**（W1.6，编辑器可实时展示）。这样坏文档仍能在编辑器打开修复，与 v3 口径一致。

## Round 4 · W1 完成（lint 语义层 + 装载管线串联）（2026-10-27）

**产出**
- `src/engine/v4/lint.ts`：语义 lint（docs/53 §12 其余错误码）——
  - 表达式：`V4_EXPR_SYNTAX`/`V4_EXPR_ROOT`/`V4_EXPR_PATH`（按层根集合 + 静态路径校验：q.<col>/q.state.<key>/t.<key>/args.<key>/local.<key>/v.<key>/run 四键/event 两键）；
  - 写权限：`V4_WRITE_DENIED`（flow 只能 v.*/local.*；behavior 只能 q.state/t/local，声明校验；flow 隐式 local 由 ask/foreach/assign 收集）；
  - 组件契约：`V4_UNKNOWN_METHOD`（call 命令 / assign-query 查询）、`V4_UNKNOWN_EVENT`（waitShell/on 组件事件 + 内部 emit↔on 配对警告）；
  - 图语义：`V4_UNREACHABLE`、`V4_UNSETTLED_FLOW`、`V4_ASK_AFTER_FINISH`、`V4_BEHAVIOR_NO_RETURN`；
  - 绑定表达式同样做层根 + 路径校验。
- `src/engine/v4/expr.ts` 增量：`collectExprPaths`/`exprPaths`、`V4ExprCheck` 带 `code`（syntax/root/function），供 lint 映射错误码。
- `src/library/validate.ts`：`loadLevelDocV4` 串联 lint——组件契约由装载管线从 `allContracts()` 注入（引擎层不反向依赖 runtime）；语义 error 也作为 `lintWarnings` 返回，保证坏逻辑文档可打开修复。
- 测试：`src/engine/v4/lint.test.ts` 17 项（基线/表达式/写权限/契约/图语义/绑定）。

**验证证据**
- `npx vitest run src/engine/v4 src/test/v4` = **6 文件 / 91 测试全绿**。
- `npx tsc --noEmit` exit 0。
- 全量回归 `npm test` = **120 文件 / 1110 测试全绿（41.11s）**，v3 零回归。

**偏差与决策**
- lint 的组件契约通过 `ctx.contractOf` 注入而非引擎直接 import `runtime/store`（遵守 graphProgram.ts 既有「引擎不反向依赖运行时」口径）；契约缺失时跳过契约类检查。
- `V4_UNKNOWN_COMPONENT` 不单独实现：target 不存在/跨层已由 validate 的 `V4_NODE`/`V4_REF` 在装载阶段拦截，避免双报。
- 语义层 error 不阻断装载（转为 lintWarnings），与 v3「坏逻辑也能打开修」口径一致；编辑器保存/AI 写入等强校验路径后续可在 W5 叠加「按 error 级拦截」。

**W1 验收结论**：task-1 全部工作项（W1.2–W1.7）完成；v4 数据内核 91 项测试 + 全量回归 1110 项全绿；接口与 docs/53 一致。关闭 task-1，进入 W2。
