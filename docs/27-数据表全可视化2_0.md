# 27 · 数据表全可视化 2.0：音符串时序内化 + 五线谱编辑 + scoring 数值化

> 状态：已落地（批次 1-5，测试 382/382）。
> 提交链：`c1ed790`（音符串时序）→ `e58816d`（scoring 数值化）→ `b16fe02`（节点图列下拉）→ 五线谱编辑器 → 收口。

## 1. 背景与动机

用户反馈数据表仍存在「手写 JSON」路径与隐式行为：

1. 新建关卡默认列（data/scoring）**无 type**、行值为 `{}`/`{max:10}` 对象 → 文本列
   `String(对象)` 渲染出 **"[object Object]"**（blankLevelDoc 未过 normalize 的模板缺陷）；
2. scoring 默认是 JSON `{"max":10}`——「分值」对作者应该就是一个数字；
3. sound/synth 播放的 `mode`（同时/按时值）参数把时序信息留在调用侧而非数据侧；
4. 音符串列的编辑是单音 chips（逐音选音名/时值），应直接在五线谱上编辑；
5. sound 应能直接播放数据表中的音符串列。

## 2. 音符串时序模型（核心设计）

`Note` 类型扩展（可选字段，向后兼容）：

| 字段 | 说明 |
|---|---|
| `midi?` | 音高（休止符可缺省） |
| `dur?` | 时值记法（缺省 `4n`；附点 `.` = ×1.5） |
| `vel?` | 力度 1-127 |
| **`t?`** | **起始拍**（四分音符 = 1 拍，相对播放起点）。缺省 = 接在前一音之后（旋律连排）；**相同 t = 同时响（和弦）** |
| **`rest?`** | 休止符：占时值推进游标，不发声 |

**播放完全由数据决定**：`audio.ts` 新增纯函数 `scheduleNoteEvents`（游标推进：无 t 接排、
有 t 跳跃、rest 占位），钢琴/合成器两条通道共用；chord/seq 分支与 25ms 微琶音删除。

### mode 兼容层（旧档声音零变化）

- UI 删除「播放方式」下拉；契约签名去 mode。
- 运行时兼容键：`args.mode === 'chord'` → 全音折算 t:0（同时，console.warn 废弃提示）；
  `'seq'` → 静默忽略（接排 = 原 seq 语义）。
- 迁移器 `normalizePlayModes`（幂等）：**已有 mode 键原样保留**（chord/seq 均为兼容键，
  仅规范化引号为单引号）；只对真正缺失 mode 的旧缺省 chord 调用显式化——多音字面量数组
  每音补 `t: 0`、动态引用补写 `mode: 'chord'`。
- **教训（幂等陷阱）**：初版「删除 seq 键」的规则不自洽——旧档 seq 删除后变成「缺 mode」，
  二次迁移会按「旧缺省 chord」再补 `mode: 'chord'`，同一条调用两次迁移结果不同。
  修正：兼容键只增不改不删，样例从 v1 夹具重新生成保证 golden 逐字段恒等。

## 3. scoring 数值化（连存量迁移，用户裁决）

- 迁移器 `structureScoringColumn`：key 为 `scoring` 的列，行值 `{max:N}` → `N`；
  改写后非空值全为数值 → 列 type 置 `number`（幂等：数值形态原样保留）。
- 迁移器 `rewriteScoringExpr`：图上全部表达式文本 `q.scoring.max` → `q.scoring`
  （call args / branch cond / assign（含查询调用）/ loop / wait / emit payload 全覆盖）。
- `blankLevelDoc` 模板：data 列 `type:'json'`、scoring 列 `type:'number'`（默认 10）。
- golden 双跑适配：v1 侧用**原始 v1 行**（scoring 对象配 v1 表达式 `q.scoring.max`），
  v3 侧用迁移行（数值配改写后的 `q.scoring`）——语义等价而非数据等价。

## 4. [object Object] 修复

  （引导 JSON 弹层修正），不再 `String(对象)`。

## 6. 五线谱编辑器（标准交互）

- `StaffEditorModal`（弹窗）：时值下拉（1n~32n）+ 附点开关、音符/休止符模式、
  「+ 休止符」按钮、「与上一音同时」复选（和弦叠加）、♯/♭/♮ 半音调整（选中时）、
  删除（按钮/Del 键）、▶ 试听（走新调度）、清空。
- 谱面交互：点击谱线按 y 位置换算音高添加音符（diatonic 换算 `dnToMidi`，顶线 = F5，
  黑键经选中后 ♯/♭ 调整）；点击音符头选中（StopPropagation 防误加）。
- `StaffPreview`：数据表单元格内嵌只读迷你谱（只显示一行，超出隐藏），点击打开弹窗；
  尺寸随列宽/行高适配（行高最小 56px 由内容撑开）。
- 纯函数导出可单测：diatonic 换算、`startBeats`/`cursorBeat`（与运行时同一游标语义）、`withDot`。
- VexFlow 5 几何 API：`stave.getYForLine(0)`（顶线）/ `getSpacingBetweenLines()`。
- 命中区防错位：`g.vf-stavenote` 数量与 notes 长度不一致时整体跳过命中区（休止符防护）。

## 7. 已知边界（记录在案）

- 五线谱点击只定位白键（diatonic），黑键需选中后 ♯/♭——交互简化，后续可加拖拽微调。
- 数据表迷你谱按整行格式化压缩绘制（VexFlow 自动挤排），超长音符串只显示前几个音。
- 兼容键 `mode: 'chord'/'seq'` 在数据中可见（UI 不可见、PlayArgsEditor 序列化原样保留）；
  新写的音符串不应再带 mode。
- 迁移器对「缺 mode 的多音字面量」补 `t: 0` 而非补兼容键——两者调度等价，数据更干净。
- 音高点击换算假定 treble 谱号（音符串编辑器固定 treble 渲染）。
