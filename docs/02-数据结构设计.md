# 音乐练习 UGC 平台 · 数据结构设计 v0.1

> 配套：[01-预研报告.md](./01-预研报告.md) · 机器可校验版：`schemas/*.schema.json`
> 本文是规范的**人读版**，两处需保持同步；冲突时以 `schemas/` 为准。

## 0. 设计原则

1. **一切皆文档（Document）**：系列、专题、关卡、乐器档案、资产包都是同一种信封下的 JSON 文档，可独立校验、独立分发。
2. **自包含可分发**：文档只通过 `refs` 声明弱依赖（id + 版本范围），导出时按 refs 闭包打包；导入时校验闭环。不做只有本地才能表达的结构，未来可直接搬上服务端。
3. **题目 = 纯数据**：关卡逻辑是模板，题目注入数据。绝大多数新题 = 复制一个 JSON 对象改几个字段，不需要碰逻辑。
4. **可校验优先**：schemaVersion 显式版本化；Ajv 校验所有文档；逻辑层另有一组 lint 规则（悬空引用、环、预算）。
5. **值可序列化**：组件间流动的一切信号都是受限的可 JSON 化类型，为未来"录制回放 / 网络对战 / 后端判分"留路。

## 1. 信号值类型系统

组件契约与逻辑系统共享的最小类型集（运行时即 TypeScript 类型，schema 中以字符串名义类型标注）：

| 类型 | JSON 形态 | 说明 |
|---|---|---|
| `number` / `string` / `boolean` / `null` | 原生 | 基础标量 |
| `Note` | `{"midi": 60, "dur": "4n", "vel": 0.8}` | `dur` 用 Tone.js 时值记法（`4n`=四分音符），可省略 |
| `Note[]` | `Note` 的数组 | 和弦/旋律 |
| `MusicDoc` | 见下 | 谱面渲染器与发声器共享的音乐数据 |
| `any` | 任意 JSON | 题目自由数据区 |

```jsonc
// MusicDoc：POC 级最小记谱语义，够渲染与发声即可，后续按需扩展
{
  "notes": [ { "midi": 60, "dur": "4n" }, { "midi": 64, "dur": "4n" } ],
  "clef": "treble",          // treble | bass
  "timeSig": [4, 4],
  "tempo": 90,
  "key": "C"
}
```

设计要点：`midi` 编号是唯一音高真相（渲染、发声、校音、指法互相换算全走 midi）；音名（`C4`）只是展示层，由 tonal 换算。

## 2. 资源信封（envelope）

所有文档共用：

```jsonc
{
  "schemaVersion": 1,
  "kind": "level",                    // series | topic | level | instrument | assetPack
  "id": "res_01J9ZK...",              // ULID，全局唯一、不可变
  "version": "1.0.0",                 // semver，内容变更必须升版
  "meta": {
    "title": "听音点击 · 入门",
    "description": "听和弦，点击五线谱上对应的音",
    "author": { "name": "someone", "contact": "" },
    "tags": ["练耳", "入门"],
    "locale": "zh-CN",
    "license": "CC-BY-4.0",
    "difficulty": 1                   // 1-5，展示用
  },
  "refs": [                           // 依赖清单：导出/导入/校验的依据
    { "id": "res_01J9PI...", "kind": "instrument", "version": "^1.0.0" }
  ],
  "content": { /* 按 kind 而定，见下文各节 */ }
}
```

- **series.content**：`{ "topicIds": ["res_..."], "coverAsset": "asset:..."? }`
- **topic.content**：`{ "levelIds": ["res_..."], "brief": "" }`
- 引用一律弱引用：导入校验时检查"所引资源要么在包内、要么已在本机库中且版本匹配范围"。

## 3. 关卡文档（level）—— 核心

`level.content`：

```jsonc
{
  "components": [ /* ComponentInstance，见 3.1 */ ],
  "logic":         { /* LogicProgram，见 3.2 */ },
  "questions":     [ /* Question，见 3.3 */ ],
  "flow":          { /* 出题与通过规则，见 3.4 */ }
}
```

### 3.1 组件实例（ComponentInstance）

```jsonc
{
  "id": "staff1",              // 关卡内唯一；逻辑系统以 "组件id.事件/命令" 寻址
  "type": "staff",             // 组件注册表键
  "name": "题目谱面",           // 编辑器/无障碍显示名
  "visible": true,             // false = 隐形功能组件（发声器、计时器等）
  "layout": { "x": 40, "y": 80, "w": 640, "h": 160 },   // 画布绝对坐标；编辑器拖放产生
  "props": { "clef": "treble", "clickable": true },      // 静态配置，须过该组件 propsSchema
  "bindings": { "music": "$q.data.music" }               // 随题目注入的数据绑定，见下
}
```

**bindings 语义**：键 = 组件声明的绑定槽位，值 = 引用串或常量。运行器在每题装载时解析一次，把值作为只读数据交给组件。引用语法：

| 语法 | 含义 |
|---|---|
| `"$q.data.music"` | 当前题目的 `data.music`（`$q` = 整个 Question 对象） |
| `"$q.prompt.text"` | 题面文本 |
| `"固定文字"` | 非 `$` 开头 = 字面量 |

### 3.1.1 组件统一契约

每种组件类型在**组件注册表**中声明契约，逻辑系统只能看见契约——这是"不同组件、统一接口"的落点：

```jsonc
{
  "type": "staff",
  "displayName": "五线谱",
  "category": "music",                       // music | ui | hidden
  "events":   {                              // 组件 → 引擎（带负载的事件）
    "noteClicked": { "midi": "number", "name": "string" }
  },
  "commands": {                              // 引擎 → 组件
    "highlight": { "target": "any", "style": "string" },
    "clear":     {}
  },
  "state":    { "selectedNote": "Note?" },   // 可读状态（供表达式读取，v1 经事件即可覆盖）
  "bindings": { "music": "MusicDoc" },       // 随题注入槽位
  "propsSchema": { /* JSON Schema */ }
}
```

POC 组件契约一览：

| type | events | commands | bindings | 备注 |
|---|---|---|---|---|
| `staff` | `noteClicked{midi,name}` | `highlight{target,style}` `clear` | `music` | VexFlow 渲染，音符头可点击 |
| `sound` | `playDone` | `play{notes}` `stop` | — | 常设为隐形；smplr 采样钢琴 |
| `label` | — | `show{text,tone}` | — | tone: `info/success/error` |
| `button` | `clicked` | `setEnabled{enabled}` `setText{text}` | — | |
| `choice` | `chosen{index,value}` | `reveal{correctIndex}` `reset` | `options` | 选择题选项组 |
| `level`（内置伪组件） | `started` `questionLoaded{index,total}` `finished{score,passed}` | `next` `restart` | — | 运行器本身，生命周期与流程控制 |

后续组件（阶段 2+）：`fingering`（渲染 instrument 档案 + `highlight` 命令）、`drums`（节奏网格显示 + tap 采集）、`tuner`（校音事件流）、`slider`、`input`、`timer`（隐形：`tick{count}` 事件 + `start/stop` 命令）。

### 3.2 逻辑程序（LogicProgram）

**统一运行时语义：事件驱动 ECA + 安全表达式。** 节点图（v2）与脚本节点（v3）都编译/降级到这一层。

```jsonc
{
  "variables": { "score": 0, "attempts": 0 },     // 关卡级变量，初始值必须是字面量
  "rules": [
    {
      "id": "check-answer",
      "on": "staff1.noteClicked",                 // 事件源："组件id.事件名"，含 level.started 等
      "when": [ "event.midi == q.data.answerMidi" ],  // 条件表达式，全部为真才执行 do
      "do": [
        { "cmd": "sound1.play",   "args": { "notes": "$q.data.rewardChord" } },
        { "cmd": "staff1.highlight", "args": { "target": "$event.midi", "style": "correct" } },
        { "cmd": "feedback.show", "args": { "text": "答对了！", "tone": "success" } },
        { "set": "score", "expr": "v.score + q.scoring.max" },
        { "cmd": "nextBtn.setEnabled", "args": { "enabled": true } },
        { "emit": "level:correct" }               // 内部事件（冒号约定），可被其他规则 on
      ],
      "else": [
        { "cmd": "sound1.play",   "args": { "notes": "$q.data.wrongBuzz" } },
        { "cmd": "feedback.show", "args": { "text": "再听一次", "tone": "error" } },
        { "set": "attempts", "expr": "v.attempts + 1" }
      ]
    }
  ]
}
```

**规则字段**：`on`（必填）、`when`（可选，表达式数组）、`do`（必填）、`else`（可选）。
**动作三型**：
- `{"cmd": "组件id.命令", "args": {...}}`：args 内字符串值支持深度引用解析（`$q.…` 路径引用、`$expr:` 前缀表达式）
- `{"set": "变量名", "expr": "…"}`：写变量
- `{"emit": "事件名", "payload": {...}}`：发内部事件（`组件id.事件名` 形态留给组件，作者事件用 `名字:名字` 避免撞车）

#### 表达式语言（"简易代码"）规范

- 语法：算术 `+ - * / %`、比较 `== != < <= > >=`、逻辑 `&& || !`、三元 `?:`、字符串拼接 `+`、成员访问 `.`、函数调用、括号。**没有**赋值、循环、下标赋值、`new`。
- 作用域根（成员访问仅允许从它们出发）：`event`（当前事件负载）、`q`（当前题目对象，含 `q.data.*` 与 `q.scoring.*`）、`v`（变量）。
- 函数白名单（可扩展，均无副作用）：`abs min max round floor ceil`、`random randomInt(a,b)`、`len(x)`、`now()`（AudioContext 时钟秒）、`midiToName(n)` `nameToMidi(s)`、`cents(f, midi)`。
- **步数预算**：单次求值节点数上限（默认 1000），超限抛错并中断该规则；规则触发链有传播深度上限（默认 32），防 A→B→A 死循环。
- 解析在装载时完成（提前暴露语法错误），求值在运行时进行。

#### 逻辑 lint（导入/保存时执行）

1. `on`/`cmd` 引用的组件 id 与事件/命令名必须存在于注册表及本关卡组件实例
2. `set` 的变量必须在 `variables` 声明；表达式标识符路径必须可从作用域根解析
3. 规则触发图无环（`emit` 闭包分析）
4. 每个 `bindings` 引用路径必须在至少一个题目里存在（或给出警告）
5. 步数预算与规则数、组件数上限（防滥用，数值待定）

### 3.3 题目（Question）

```jsonc
{
  "id": "q1",
  "prompt": { "text": "听 —— 点击你听到的那个音", "audio": "asset:...", "image": "asset:..." },
  "data": {                                  // 任意 JSON，$q.data 的内容，题目之间完全自由
    "music":      { "notes": [{"midi":60},{"midi":64},{"midi":67}], "clef": "treble" },
    "answerMidi": 64,
    "listenChord": [ { "midi": 64, "dur": "2n" } ],
    "rewardChord": [ {"midi":60},{"midi":64},{"midi":67},{"midi":72} ],
    "wrongBuzz":   [ { "midi": 43, "dur": "8n" } ]
  },
  "scoring": { "max": 10 },                  // 语义由关卡逻辑定义（表达式经 q.scoring 读取）
  "hints":    [ { "text": "中央C左边的那个E" } ],
  "explanation": "E4 位于第一线之上……"
}
```

复杂题目可携带 `"logicPatch"`（对关卡 rules 的合并补丁，merge 语义 v1 只支持"追加规则/覆盖变量初值"），实现从"数据驱动"到"单题定制"的渐进，不用二选一。

### 3.4 流程（flow）

```jsonc
{
  "order": "sequential",       // sequential | shuffle
  "count": null,               // null=全部；N=每次抽取 N 题（shuffle 时有意义）
  "pass":  { "expr": "v.score >= 20" }   // 结束时求值；结果进 level.finished 负载
}
```

## 4. 乐器档案（instrument）—— 指法显示器的数据源

指法/把位显示不写死任何乐器，乐器本身是 UGC 资源：

```jsonc
{
  "kind": "instrument", "id": "res_...", "version": "1.0.0", "meta": { "title": "41寸古典吉他" },
  "content": {
    "type": "fretboard",                       // fretboard | keyboard | custom
    "tuning":  [ { "midi": 40 }, { "midi": 45 }, { "midi": 50 }, { "midi": 55 }, { "midi": 59 }, { "midi": 64 } ],
    "frets": 12,
    "noteMap": { "64": [ { "string": 1, "fret": 0 }, { "string": 2, "fret": 5 } ] },  // midi → 可视位置
    "shapes":  { "C大调开放和弦": [ { "string": 2, "fret": 1 }, { "string": 4, "fret": 2 }, { "string": 5, "fret": 3 } ] }
  }
}
```

`fingering` 组件 = 渲染某 instrument 档案 + `highlight`/`clear` 命令 + `posClicked` 事件，与逻辑系统完全通过统一契约交互。钢琴档案的 `noteMap` 即键位表；`custom` 允许上传几何描述（口风琴、竖笛、手号等）。

## 6. 资产与引用

- 资产引用形如 `"asset:<ulid>"`；assetPack 文档携带资产清单（name/mime/bytes 内容或外链）。
- 导出含资产的关卡/系列时，按 refs 闭包打成 `.zip`（fflate）；纯 JSON 关卡就是单文件。
- 导入管线：Ajv 校验 → refs 闭包检查（缺件则拒绝并列出缺件）→ id 冲突策略（同 id 同 version 跳过 / 同 id 不同 version 另存为新草稿）。

## 7. 版本与演进

- `schemaVersion` 整数递增；不兼容变更必须提供迁移器（导入时 `v1→v2` 自动升级并标注）。
- 组件注册表独立版本化：关卡声明依赖的组件能力集，老文档遇到新组件缺位时给出"组件缺失"降级提示而不是崩溃。
- `refs.version` 用 semver range（`^1.0.0`），导入时按本机库最优匹配解析。
