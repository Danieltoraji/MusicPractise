## 1. 背景与目标

项目当前是**纯静态离线应用**（GitHub Pages，无后端，零网络代码）。规划为关卡编辑器引入 AI 辅助创作能力，让创作者用自然语言驱动内容生产。总体分五个批次，依赖关系决定顺序：

| 批次 | 内容 | 入口 | 状态 |
| --- | --- | --- | --- |
| 0 | AI 基础设施：供应商注册表 / 设置页 / chat 客户端 | 首页设置按钮 + 顶栏 ⚙ + `#/settings` | ✅ 本次 |
| 1 | AI 伪代码生成 / 编辑 | 编辑器 · 伪代码页（ScriptTab 工具栏） | 规划 |
| 2 | AI 节点图解释 + 生成 / 改写 | 编辑器 · 节点图工具栏 | 规划 |

## 2. 核心设计裁决

### 2.1 伪代码是 AI 的统一接口

`engine/script.ts` 的 `generateScript` / `parseScript` 已实现伪代码 ↔ 图 IR（GraphProgram v2）**往返恒等**，项目正式原则为「先设计代码再设计节点图」。因此批次 1/2/4 的图相关 AI 功能统一走同一条管线：

```
用户自然语言指令
  → LLM 产出 LevelScript 伪代码全文
  → parseScript 本地解析（ScriptError 带行列号）
  → lint 校验（lintGraphProgramDetailed）
  → 失败：把错误回喂 LLM 自动修复（≤1~2 轮）
  → 预览 → 用户显式应用 → doc.logic 更新 → 节点图视图自动刷新
```

LLM 输出伪代码远比输出 nodes/edges JSON 数组可靠（结构化子集、语法贴近常见代码），且完全复用既有草稿/漂移/应用机制，**零引擎改动**。

### 2.2 AI 只产草稿，本地校验 + 用户显式应用

所有 AI 产物一律不直接写入 doc：
- 伪代码 → 写入 ScriptTab 既有草稿，用户仍点「应用到节点图」；
- 数据表行 → 预览网格高亮新增行，用户确认后追加；
- 整关卡 → `loadLevelDoc`（Ajv + migrate + lint）全管线校验通过才入库。

### 2.3 浏览器直连，OpenAI 兼容单协议

纯静态站没有后端可托管密钥或做代理，因此：
- 客户端只实现一种协议：OpenAI 兼容 `POST {baseUrl}/chat/completions`（非流式，流式留作打磨）；
- 主流供应商（DeepSeek / GLM / OpenAI / Moonshot / Qwen / OpenRouter）均提供该兼容端点；
- 不兼容的服务走「自定义供应商」填兼容网关地址。

## 3. 批次 0：已落地内容

### 3.1 模块结构（`src/ai/`）

| 文件 | 职责 |
| --- | --- |
| `providers.ts` | 预设注册表 `PROVIDER_PRESETS`（id/名称/baseUrl/默认模型/模型建议/备注）+ 自定义档案 id 生成（`custom-` 前缀，程序化生成） |
| `settings.ts` | localStorage 键 `ai-settings`（惯例同 `graph-theme`：裸 kebab-case）。结构 `{activeId, profiles}`；读取时缺失预设自动补齐、毒数据回落默认 |
| `client.ts` | `chatComplete(profile, messages, opts)` + `testConnection`；错误分类 `AiClientError`：`bad-config / network / auth / rate-limit / server / bad-request / response`，全部映射为可读中文提示 |

预设供应商（2026-10 的建议模型，均可自由输入覆盖）：DeepSeek、智谱 GLM、OpenAI（ChatGPT）、Moonshot Kimi、通义千问 Qwen、OpenRouter（聚合网关，其他源浏览器直连受阻时的备选）。

### 3.2 设置界面

- 路由 `#/settings`（App.tsx hash 路由新增分支）；入口：**首页「设置」卡片**（需求点）+ **顶栏 ⚙ 设置**（全站可达）。
- `src/pages/SettingsPage.tsx`：预设供应商卡片网格（显示 baseUrl / 是否已配 Key / 当前模型）+ 「＋ 添加自定义供应商」（可命名、可删除）；右侧档案表单：名称（仅自定义）/ Base URL / 模型（datalist 建议 + 自由输入）/ API Key（password + 显隐切换）；「测试连接」用**当前表单值**发一条最小对话，显示延迟与应答或分类错误。
- 编辑只改本地 state，点「保存设置」才落盘；每个供应商档案独立记忆 Key，切换不丢。

### 3.3 安全与已知限制

- **API Key 明文存本机 localStorage**——静态站唯一可行方案；设置页显著注明「仅存本机，勿在共享电脑保存」。后续若部署后端可无缝换签发短时 token。
- **CORS 依赖供应商**：浏览器直连要求服务端允许跨域；网络层失败统一提示「改用 OpenRouter 或自定义代理地址」。
- 供应商侧内容政策 / 计费由用户自担，本应用不经手任何数据中转。

## 4. 批次路线图（后续实施细节）

### 批次 1：AI 伪代码（ScriptTab）

- 工具栏新增「AI 生成」「AI 编辑当前脚本」；弹层输入自然语言指令。
- system prompt 组装：LevelScript 语法（docs/12 EBNF 摘要 + 示例）+ 当前关卡上下文（组件 id/type/命令清单、事件清单、变量、数据表列、当前脚本全文——编辑模式）。
- 返回全文 → `parseScript` 校验 → 失败带行列号回喂重试 ≤1 次 → 预览 → 写入既有草稿（沿用漂移黄条机制，用户手动「应用到节点图」）。

### 批次 2：AI 节点图（GraphEditor）

- 「AI 解释此图」：`generateScript(logic)`（非结构化图降级为 `summarizeNode` 节点清单）→ LLM 自然语言解释 → 只读浮层（复用「查看脚本」面板样式）。
- 「AI 生成 / 改写」：复用批次 1 管线，入口放图工具栏；应用后 doc 单向流自动刷新图 + `arrangeLayout` 自动布局。

### 批次 3：AI 数据表题目（TableEditor）

- 「AI 生成题目」：上下文 = 列定义（key/label/type）+ 已有示例行（截断）+ 逻辑引用的 `q.*` 路径扫描 + 组件清单；指令如「生成 5 道三和弦听辨题」。
- 输出 JSON 行数组（优先 `response_format: json_object`，不支持时 markdown 围栏兜底提取）→ 逐格按 `DATA_APPLY_ACCEPTED_TYPES` 列类型矩阵校验（notes 音符串 / scoring 数值等）→ 预览高亮 → 确认追加。

### 批次 4：AI 整关卡（资源库页）

- 入口：「AI 新建关卡」（资源库页「新建关卡」旁）。
- LLM **分节**输出：`meta / views / components（布局+props）/ script（LevelScript 伪代码，而非 nodes/edges）/ table / flow` → 本地 `parseScript` 组装 LevelDoc → `loadLevelDoc` 全管线校验 → 失败自动修复 ≤2 轮 → `putResource` 入库 → 跳转编辑器。
