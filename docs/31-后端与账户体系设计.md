# 31 - 后端与账户体系设计

> 状态：批次 B1–B3 已落地（B1 认证地基 2026-10-11；B2 云盘 + B3 通关同步 2026-10-12）；B4 管理后台 / B5 安全加固待实施
> 关联：docs/01（原预研报告·部署为零后端静态站）、README §部署（双通道 → 本文档裁决为 Workers 单通道）

## 1. 需求与边界

### 1.1 需求

将纯前端应用扩充为前后端兼备，当前阶段后端提供四组能力：

1. **账户**：注册、登录、信息管理。用户信息仅昵称 + 密码（无邮箱）。
2. **匿名兼容**：未登录用户可访问所有现有资源（练习、关卡编辑、导入导出等）——登录态是纯叠加，不是门槛。
3. **登录用户**：
   - **云盘**：可将不超过 10 个关卡上传云端，上传后本人可随时下载访问；
   - **通关记录**：后台记录用户各关卡的完成状态（对应本地 `progress` 表的 `bestScore / passed / attempts`）。
4. **管理员**：管理后台——管理所有用户信息、关卡内容，允许修改管理员密码。
5. **非功能**：按日活 50 人做负载预估，结合免费额度选择后端形态；HTTPS + 初步反攻击能力。

### 1.2 边界裁决

- **本轮仅输出规划**（本文档），代码实施按 §8 批次 B1–B5 后续逐批推进，每批独立提交 + 全量测试门禁。
- **注册开放**，无邀请码/审核；无邮箱意味着无法自助找回密码——密码丢失 = 账号丢失，管理员可手动重置（§6.7），此取舍写入 UI 文案。
- **云关卡私有**：仅本人与管理员可见可下载，不做公开分享/广场（远期候选，不在本期）。
- **放弃 GitHub Pages 通道**（用户裁决「为了没有后顾之忧」）：站点收敛为 Cloudflare Workers 单通道，详见 §3。
- **本地能力不变**：无后端/离线/未登录时应用全功能可用，现有 Dexie/localStorage 数据流原样保留；云能力全部走增量同步，绝不在同步失败时阻塞本地路径。
- 关卡内容管理（管理员）本期指**云端关卡**（cloud_levels）；内置关卡在仓库内、用户本地关卡在本机 IndexedDB，均不在服务端管辖范围。

## 2. 选型与负载测算

### 2.1 候选对比

| 维度 | **Cloudflare Workers + D1（选定）** | 独立 Node 服务（免费 VPS/容器） | BaaS（Supabase 等） |
|---|---|---|---|
| 与现有部署契合 | 同一 Worker 原地扩展，`wrangler.jsonc` 注释已预留升级路径，CI 零结构变化 | 新增服务器，与现有 Cloudflare 管线脱节 | 前端直连 SDK，无自有后端 |
| 运维成本 | 零（无服务器） | 证书/反代/进程守护/防火墙全自助 | 低，但控制台配置不可版本化 |
| 免费额度 | 10 万请求/天、D1 500 万行读/天 | 普遍休眠或限时回收 | 有项目数/暂停策略 |
| HTTPS/反攻击 | 边缘自动签发 + 免费 DDoS 吸收 | Let's Encrypt + fail2ban 自助 | 平台托管 |
| 主要风险 | workerd 运行时约束（CPU 时间、密码哈希迭代上限，见 §6.1/§10） | 休眠、单点、被回收 | 厂商绑定、RLS 配错即越权、管理后台仍需自建 |

**结论**：在现有 `musicpractise` Worker 上原地扩展 Workers + D1。依据：升级路径零结构变化；免费额度对目标负载余量 20 倍以上（§2.2）；HTTPS 与反攻击由平台自带；50 DAU 规模下无需为「独立服务的主导权」支付运维成本。

### 2.2 负载测算（50 日活 vs 免费额度，2026-10 核实）

| 指标 | 预估用量（50 DAU） | Workers/D1 免费额度 | 余量 |
|---|---|---|---|
| 请求数 | ~5,000/天（人均 100 次页面资源 + API） | Workers 100,000/天 | ~20× |
| 单请求 CPU | 登录最重（PBKDF2，实测定档 ≤10ms）；其余为 token 摘要 + 1–2 条 D1 查询 | 10ms CPU/请求 | 需 B1 实测（§6.1） |
| D1 行读 | ~10,000 行/天（每请求会话行 + 业务行 ≤3 行） | 5,000,000 行/天 | ~500× |
| D1 行写 | ~2,500 行/天（通关上报为主） | 100,000 行/天 | ~40× |
| 存储 | 50 人 × 10 关 × 25KB ≈ 12.5MB | 5GB | ~400× |

注：自 2026-09-01 起 D1 免费档超日限为硬失败（此前为软限），但按上表余量不可能触及。远期若用户量级上台阶，Workers 付费档（$5/月）即可解锁 30s CPU 与量级配额，架构无需迁移。

## 3. 部署拓扑（Workers 单通道）

### 3.1 裁决

放弃 GitHub Pages，**站点唯一入口 = `https://musicpractise.danieltoraji.workers.dev/`**：同一 Worker 先接 `/api/*`（`run_worker_first`），其余路径全部回落静态资产（SPA fallback 不变）。静态与 API 同源，Cookie 天然 first-party，无 CORS、无跨域 Cookie 问题。

理由：双通道下「Pages 无云功能」造成同一应用两种体验的割裂；单通道后前端无需按通道区分叙事，`VITE_BASE` 差异化构建随之消失。

- 原 Pages URL（`danieltoraji.github.io/MusicPractise/`）停更失效，可在仓库 Settings → Pages 关闭。
- 保留启动探测 `/api/health`：职责收窄为本地 dev（vite 无 API）与后端异常时的降级提示，不再承担通道差异。
- 远期可选：绑定自定义域，HTTPS 仍由 Cloudflare 自动签发。

## 4. 数据模型（D1 / SQLite）

```sql
-- migrations/0001_init.sql
CREATE TABLE users (
  id          TEXT PRIMARY KEY,            -- ULID（复用 res_ 同款 Crockford Base32 形态，服务端 crypto 随机生成）
  nickname    TEXT NOT NULL UNIQUE COLLATE NOCASE,  -- 大小写不敏感唯一；NFC 归一后入库
  pw_hash     TEXT NOT NULL,               -- 'pbkdf2$<iter>$<saltB64>$<hashB64>'，见 §6.1
  role        TEXT NOT NULL DEFAULT 'user' CHECK (role IN ('user','admin')),
  status      TEXT NOT NULL DEFAULT 'active' CHECK (status IN ('active','disabled')),
  created_at  INTEGER NOT NULL,            -- epoch ms
  updated_at  INTEGER NOT NULL
);

CREATE TABLE sessions (
  id           TEXT PRIMARY KEY,           -- SHA-256(token) 的 hex；token 本体只在 Cookie
  user_id      TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  created_at   INTEGER NOT NULL,
  last_seen_at INTEGER NOT NULL,
  expires_at   INTEGER NOT NULL            -- 30 天滑动续期，见 §6.2
);

CREATE TABLE cloud_levels (
  id             TEXT PRIMARY KEY,         -- 云端槽位 ULID
  user_id        TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  level_id       TEXT NOT NULL,            -- 关卡信封 id（res_*）
  title          TEXT NOT NULL,            -- 冗余 meta.title 供列表展示
  payload        TEXT NOT NULL,            -- 完整 LevelDoc JSON（schemaVersion 3）
  bytes          INTEGER NOT NULL,
  schema_version INTEGER NOT NULL,
  created_at     INTEGER NOT NULL,
  updated_at     INTEGER NOT NULL,
  UNIQUE (user_id, level_id)               -- 同一关卡重复上传 = 覆盖其云端槽位
);
CREATE INDEX idx_cloud_levels_user ON cloud_levels(user_id);

CREATE TABLE progress (
  user_id    TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  level_id   TEXT NOT NULL,
  best_score REAL NOT NULL DEFAULT 0,
  passed     INTEGER NOT NULL DEFAULT 0,   -- 0|1，只升不降
  attempts   INTEGER NOT NULL DEFAULT 0,
  updated_at INTEGER NOT NULL,
  PRIMARY KEY (user_id, level_id)
);

CREATE TABLE audit_log (
  id          TEXT PRIMARY KEY,
  actor_id    TEXT,                        -- 操作者（可为空=系统）
  action      TEXT NOT NULL,               -- 'user.disable' / 'admin.reset_password' / 'cloud.delete' …
  target_type TEXT NOT NULL,
  target_id   TEXT NOT NULL,
  detail      TEXT,                        -- JSON 摘要，不含敏感字段
  created_at  INTEGER NOT NULL
);
```

设计要点：

- **昵称唯一 COLLATE NOCASE**：防「Alice / alice」双号歧义；NFC 归一在服务端做，杜绝同形异码注入。
- **sessions 存 token 摘要**：库被拖走也无法伪造会话（token 只在 HttpOnly Cookie）。
- **cloud_levels 以 (user_id, level_id) 唯一**：上传语义收敛为「同一关卡覆盖更新」，10 上限按去重后的关卡数计；`UNIQUE` 约束兜底并发双击。
- **progress 复刻本地 `ProgressRecord` 形态**（`src/library/db.ts`）：`bestScore/passed/attempts/updatedAt` 同名同义，同步合并规则见 §7.4。
- 所有时间戳 epoch ms INTEGER，与前端 `Date.now()` 直接对齐。

## 5. API 契约

统一约定：路径前缀 `/api`；请求/响应 JSON（下载端点除外）；Cookie `mp_session` 承载会话；错误信封统一 `{ "error": { "code": "...", "message": "<中文，可直接展示>" } }`；认证端点未登录返回 401。`/api/auth/me` 例外：未登录返回 200 `{ "user": null }`，避免启动探测刷 401 噪音。

### 5.1 认证

| 端点 | 请求 | 成功响应 | 主要错误 |
|---|---|---|---|
| `POST /api/auth/register` | `{nickname, password}` | `{user}` + 置 Cookie | 400 昵称/密码不合规则；409 昵称已占用；429 限流 |
| `POST /api/auth/login` | `{nickname, password}` | `{user}` + 置 Cookie | 401（用户不存在与密码错误同一响应、同耗时路径）；429 |
| `POST /api/auth/logout` | — | `{ok:true}` + 清 Cookie | — |
| `GET /api/auth/me` | — | `{user: {id, nickname, role}}` 或 `{user: null}` | — |
| `PATCH /api/auth/nickname` | `{nickname}` | `{user}` | 400/409/401 |
| `POST /api/auth/password` | `{oldPassword, newPassword}` | `{ok:true}`（改密后吊销其余会话） | 401 旧密码错误；400 |

`user` 形态：`{id, nickname, role}`，绝不回传 `pw_hash`。昵称规则：2–24 字符、NFC 归一、trim 后非空、无控制字符；密码规则：≥8 字符（不做复杂度强制，UI 给建议）。

### 5.2 云盘（登录态；仅本人 + admin）

| 端点 | 语义 | 主要错误 |
|---|---|---|
| `GET /api/cloud/levels` | 槽位列表（元数据，不含 payload）：`{levels: [{id, levelId, title, bytes, schemaVersion, createdAt, updatedAt}], used, limit: 10}` | 401 |
| `POST /api/cloud/levels` | 上传/覆盖：`{levelId, title, payload}`；按 `(userId, levelId)` upsert | 409 超过 10 关；413 超限；400 校验失败；429 |
| `GET /api/cloud/levels/:id` | 下载：`{level: {...元数据, payload}}` | 404（他人关卡同样 404，防探测） |
| `PUT /api/cloud/levels/:id` | 覆盖更新 payload/title（重校验） | 同上 |
| `DELETE /api/cloud/levels/:id` | 删除槽位 | 404 |

上传约束：`payload` 字节 ≤ **512KB**（实测关卡 10–25KB，50 倍余量；Content-Length 预检 + 实读字节双查）；服务端跑与前端同一套 Ajv 信封校验（§6.5）；拒绝 `__proto__/constructor/prototype` 键（§6.5）。

### 5.3 通关记录（登录态）

| 端点 | 语义 | 主要错误 |
|---|---|---|
| `GET /api/progress` | 全量拉取：`{records: [{levelId, bestScore, passed, attempts, updatedAt}]}` | 401 |
| `PUT /api/progress` | 批量 upsert：`{records: [...]}`，单次 ≤500 条，字段钳制后写库 | 400 超批量；429 |

### 5.4 管理（role=admin，普通用户一律 403 + 写审计）

| 端点 | 语义 |
|---|---|
| `GET /api/admin/users?query=&limit=&offset=` | 用户列表（含 status/role/created_at，不回 pw_hash） |
| `PATCH /api/admin/users/:id` | 改昵称 / 禁用·启用 / 重置密码 / 调整 role；禁止对自己降权或删除（防锁死） |
| `DELETE /api/admin/users/:id` | 删除用户（级联清 sessions/云盘/进度，写审计） |
| `GET /api/admin/levels` | 全站云盘关卡列表（含属主昵称） |
| `DELETE /api/admin/levels/:id` | 删除违规关卡（写审计） |
| `GET /api/admin/audit?limit=` | 审计日志倒序分页 |

### 5.5 探测

`GET /api/health` → `{ok: true, time}`，无副作用无鉴权，前端启动探测用。

## 6. 认证与安全设计

### 6.1 密码哈希（免费版 10ms CPU 红线内的取舍）

- 算法 **PBKDF2-SHA256**（WebCrypto `crypto.subtle`，workerd 与 Node 22 同源实现，前后端/种子脚本共用一套代码）；每用户 16B 随机盐；存储格式 `pbkdf2$<iter>$<saltB64>$<hashB64>`，迭代数随哈希自描述，未来升级算法/轮数无需迁移即可并存验证。
- **迭代数单点常量，B1 实测定档（已定稿）**：`worker/password.ts` 的 `PBKDF2_ITERATIONS = 100_000`。wrangler dev 实测（本机 Windows / workerd）：注册请求总耗时 92ms、登录 71ms（含 D1 读写与建会话），无 1102 CPU 超限、无迭代上限报错——100k 档成立，不再降档。升级算法/轮数时旧哈希按自述迭代数并存验证。
- **防枚举**：用户不存在与密码错误返回同一 401 信封，且两者都执行一次等量 PBKDF2（对随机假盐求哈希）拉平耗时。

### 6.2 会话

- token：32B `crypto.getRandomValues` → base64url；DB 只存 `SHA-256(token)`。
- Cookie：`mp_session=<token>; HttpOnly; Secure; SameSite=Lax; Path=/; Max-Age=2592000`。
- 30 天滑动续期：校验通过且剩余 <15 天时刷新 `expires_at` 并重置 Cookie。登出删除行 + 清 Cookie。改密成功吊销该用户全部其他会话。

### 6.3 CSRF 与请求校验

- 同源部署 + `SameSite=Lax` 已挡住跨站写；对全部写方法（POST/PUT/PATCH/DELETE）额外校验 `Origin`：host:port 与 Host 头（缺省回落请求 URL host）一致才放行，无 Origin 的非浏览器客户端放行。**开发放行（B1 实测补充）**：vite(5173) 代理转发 wrangler dev(8787) 时 Host 被改写为内部地址，故「Origin 与目标任一候选均为 loopback（localhost/127.0.0.1/[::1]）」视为同源——远程恶意页面的 Origin 不可能是 loopback，不构成生产弱点。
- 全部 SQL 经 D1 预编译参数化（`.bind()`），零字符串拼接。
- 所有请求体经手写小型校验器（`worker/validate.ts`，零依赖、可擦除语法供种子脚本复用）：类型、长度、归一化逐字段把关，校验规则单一真源。

### 6.4 限流与反爆破（B1 定稿：D1 滑窗主方案）

- **落地方案**：D1 `login_attempts` 滑动窗口（`worker/ratelimit.ts`）——登录 5 次失败/15 分钟/(IP哈希+昵称) 锁定至窗口结束（窗口内计满后继续失败不重开窗口，防无限顺延）；注册按尝试计数 10 次/小时/IP（防通过注册接口探测昵称占用）；成功登录清零；挂载路径概率性（10%）清理过期行省写放大。IP 以 `SHA-256(CF-Connecting-IP + IP_HASH_SALT 盐)` 截 8 字节落库，不存原始 IP。
- 选型理由（相对原方案的修订）：与「handler 纯函数 + D1 fake」测试策略完全兼容（Rate Limiting binding 无法在 node 环境测试）、零 wrangler 配置风险；binding 降级为远期可选优化，接口面不变可后换。
- wrangler dev 实测：连续 5 次错密码 401 → 第 6 次（含正确密码）429 `rate_limited`（提示剩余 15 分钟）；伪造 Origin 403 拦截正常。

### 6.5 上传与注入防护（B2 定稿）

- 大小：Content-Length 预检 + 实读字节双查 ≤512KB（序列化后计）；请求体上限另设 560KB（payload + 信封余量）。
- 结构：**服务端校验改用 `@cfworker/json-schema`**（B2 唯一新依赖，仅 worker 使用）——原定复用 Ajv 管线不可行：Ajv 依赖 `new Function` 动态生成校验器，workerd 禁止动态代码生成。cfworker 版为闭包式校验器，加载**同一份** `schemas/v1/level.json`（跨文件 $ref 以完整 $id 注册，7 份 schema 全量注册）；Validator 在 worker 模块顶层预编译（startup 预算，不占请求 10ms CPU）。Node 冒烟 + wrangler dev 实测双确认：真实样例通过、篡改 payload → 400 `invalid_level` 且错误可读。另发现 `Meta.additionalProperties: false`——未知 meta 键即被 schema 拒绝，与 proto 键防护互补。
- **原型污染**：递归 walk（深度上限 20）拒绝键名 `__proto__`、`constructor`、`prototype`，命中即 400。
- 一致性：payload.id 必须与 levelId 一致（POST/PUT 双路径），防止槽位键与内容错位。
- 存储即原文：payload 以文本原样入库，下载侧照走现有「信封 schema → 迁移 → lint」装载管线，服务端不解释关卡语义。

### 6.6 响应头与平台层防护（B5 实测收尾）

- 经 assets `_headers` 注入：`X-Content-Type-Options: nosniff`、`Referrer-Policy: same-origin`、`X-Frame-Options: DENY`、`Permissions-Policy`；CSP 以「实测不破站」为前提逐步收紧（首版 `default-src 'self'` + AI 供应商域 + smplr CDN + 样式所需的最小开放，随批次实测调整）。
- 平台层免费项（文档化为运维清单）：无上限 DDoS 吸收（默认开启）、Bot Fight Mode（建议开启）、WAF 自定义规则 5 条额度（可选：`/api/admin/*` 限国家/ASN）。
- `/api/admin/*` 不做任何目录式隐藏，安全完全依赖会话 + role 中间件 + 审计。

### 6.7 管理员产生与密码管理

- 种子脚本 `scripts/seed-admin.mjs`（Node 22，与服务端同一 PBKDF2 模块）：本地计算哈希，输出 `wrangler d1 execute` 用的 INSERT；昵称、密码交互式输入，绝不入库仓库。
- 管理员改自己的密码走统一 `POST /api/auth/password`（满足需求「允许修改管理员密码」）；重置他人密码走 admin API 并写审计。

### 6.8 备份与恢复

- D1 Time Travel（30 天内任意时点回溯，免费档默认开启）兜底误删/坏写。
- `npx wrangler d1 export musicpractise-db --remote --output=backup.sql` 手动导出流程文档化（B5 收尾写运维章节）。

### 7.1 通关上报与多端合并

- 上报：`LevelPage.handleFinished` 在本地 `saveProgress` 成功后，登录态则 **fire-and-forget** `PUT /api/progress`（失败静默 + console.warn，绝不阻塞/报错打扰游玩）。
- 合并（登录成功时执行一次）：拉取云端全量 → 与本地逐关按 **单调合并**（`bestScore=max，passed=或，attempts=max，updatedAt=max`）合成 → 本地写入 → 差异回推云端。规则满足交换律/幂等，重复同步、双端并发同步均收敛一致；`attempts` 取 max 而非相加，避免多端翻倍。
