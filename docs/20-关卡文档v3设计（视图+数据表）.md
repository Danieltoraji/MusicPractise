# 20 · 关卡文档 v3 设计与评审：互斥视图 + 题目数据表

> 批次目标（用户指令）：去掉 questions 体系；关卡改为互斥视图组成（views.goto 驱动 + view.entered 事件）；题目改为与变量平权的自定义字段表格（q.* 指向当前行）；模版视图承载「显示题目」抽象；自动迁移器升级 schemaVersion 3；编辑器画布升级视图管理、题目 Tab 换表格面板。
> 用户明确要求：认真再三评估，必要时可推翻指令；自主迭代不提问。

## 1. 对指令的评估与两处裁剪

指令全部成立并已落地，唯两处经评估后**裁剪/收窄**（可推翻的推翻，不成立的明说不做）：

### 裁剪一：「合并节点」与「一张大图拆几张小图」本批不做

- 指令动机是「逻辑显式化带来节点图数量爆炸」。但爆炸的两个来源在本批设计里被更便宜地消解：
  1. **视图不划分逻辑作用域**（见 §2 裁决）→ 不存在「每视图一张图」，图永远是一张，只随逻辑复杂度线性增长；
  2. 「显示题目」这类每题重复逻辑被**模版视图 + 绑定重放**吸收为数据（表格列 → 显示值的映射），不再需要每题写一遍节点。
- 「合并节点」实质是复合节点/子图，属图 IR 级变更（作用域、出口协议、脚本往返都要重定义），与视图正交且风险量大，塞进本批必然做糙。记录为独立候选批次。
- 若未来图确实膨胀，优先级排序建议：撤销/重做 > 复合节点 > 分图浏览（标签页聚焦子图）。

### 裁剪二：行门控不使用 event.row，改用系统变量 v.__row

- 初版用 `event.row == i` 做行门控——但只对 `level.questionLoaded` 成立；appendRules 编译出的规则可挂在**任意事件**（`x.ping`、`timer1.tick`）上，那些负载里没有行号。
- 最终：`LevelSession.loadRow` 把原始行号写入系统变量 `engine.vars.__row`，门控统一 `v.__row == i`。`__row` 双下划线 = 内部约定（同 `__tick` 命令），迁移器把它补进 `logic.variables = null` 声明（lint 零误报），引擎 reset 后由 start→loadRow 重写。
- `level.questionLoaded` 负载仍附加 `row`（原始行号），供表达式只读使用（shuffle 下与 index 不同）。

## 2. 必答裁决：视图是否划分变量作用域 / 逻辑图作用域？——**否，视图只作表现层边界**

| 方案 | 变量 | 逻辑图 | 后果 |
| --- | --- | --- | --- |
| **采纳：视图=纯渲染边界** | 全局 | 全局单图 | `v.score` 一字不改；事件隔离免费（非当前视图组件不渲染→不发事件）；「单一 IR 三视图」架构不动 |
| 否决：视图划分变量作用域 | 每视图 | — | `v.score` 跨视图失效，违背「已有脚本一字不改」；跨视图计分要发明导出变量，心智更重 |
| 否决：视图划分图生效范围 | — | 每视图子图 | 跨视图流程（结算页改全局分）需要新语义；图与视图耦合后拆图成为必然，复杂度爆炸 |

推论：组件事件天然视图隔离（渲染才存在）；`timer` 等不可见组件的事件跨视图持续（计时不停摆）——这是特性不是缺陷，模版页倒计时应显式 `timer.stop` 或在 `view.entered` 里 arm。

## 3. v3 数据模型

```ts
schemaVersion: 3
content: {
  views: { id, name?, template? }[]      // ≥1；template 至多一个（模版视图）
  components: ComponentInstance[]        // 新增 view?: string（缺省=首视图，装载补齐）
  logic: GraphProgram                    // 不变（v2 图 IR）
  table: { columns: { key, label? }[], rows: Record<key, Json>[] }
  flow?: FlowConfig                      // 不变（顺序/乱序/题数/通过线仍作用于表格行）
}
```

- `q.*` = 表格**当前行**的列值。迁移保留 `prompt/data/scoring`（及 hints/explanation）列 → `q.data.x`、`q.scoring.max` 一字不改。
- 行推进语义不变：`level.next` 下一行（末行结算）、`flow.order/count` 抽行、`level.restart` 复位。事件负载新增 `row`（原始行号）。

## 4. 运行时（LevelSession / LevelRunner）

- `start()`：`level.started` → 进入首视图（派发 `view.entered {view}`）→ 装载第 0 行（写 `__row` → 重放当前视图绑定 → `onRow` → `level.questionLoaded`）。
- `views.goto(id)`（call 节点，伪实例 `views`）：未知视图 → error 事件；同视图重复 goto = no-op（防 handler 自环）；切换 = 换渲染集合 + 重放该视图绑定 + 派发 `view.entered`。
- `level.next`：推进行 → 若存在模版视图则自动 `goto(模版视图)`（同视图 no-op）——**即「显示题目」抽象**：作者只需把模版视图组件映射到表格列，换行自动刷新显示。
- 绑定（`$q.<列>`/`$expr:`）重放时机 = 进视图 + 换行；非当前视图的绑定推迟到进入时应用。
- LevelRunner 只渲染 `(comp.view ?? 首视图) === 当前视图` 的组件；题面 = 当前行的 `prompt` 列（对象/字符串双形态）。

## 5. 迁移器（migrateDocToV3）

1. 逻辑先行 `migrateLogicV1toV2`（保证编译产物协议成立）；
2. 视图：沿用已有 views，否则 `[{id:'main', name:'主视图', template:true}]`；组件补 `view`；
3. 表格：列 = 各题顶层字段并集（去 `id`/`logicPatch`，出现序稳定；已知列带中文 label），行缺格补 `null`；
4. `logicPatch.variables` → 行门控装载子图（`q{i}_load → q{i}_gate(v.__row==i) → q{i}_var_<k>…`）**前置到节点数组头部**（保持旧「先补丁后处理器」时序）；`appendRules` → v1 规则迁移成图后每个 on 入口插同行门控；
5. 补丁变量与 `__row` 缺省补进 `logic.variables = null`；
6. 幂等：v3 输入短路原样返回；确定性：同输入逐字段同输出（golden 断言依赖）。
7. ⚠ 已知坑（记录）：v3 短路意味着**v3 文档的编译产物不会随迁移器升级而刷新**——内置关卡从 v1 夹具重新生成规避；用户侧仅在「先存 v3 后又降级迁移器」场景才会咬人，概率极低，接受。

## 6. 编辑器

- 画布 → **视图管理**：顶部视图条（切换 ▸ / 模版 ⭐ 单选 / 删除 × 级联删组件带确认 / + 视图）；组件面板新增组件落入当前视图；Inspector 增「所属视图」转移 + **数据映射**（契约 bindings 槽位 → 表格列下拉，产出 `$q.<列>`；高级 JSON 仍在）。
- 节点图：节点库新增**视图组**（每视图一枚「前往 X」）；Inspector 的 views.goto 特化为视图下拉（不手写 id）；lint 校验方法白名单与字面量视图存在性；画布对照图标题带视图名。
- 题目 Tab → **数据表 Tab**：列（改名/显示名/删除/添加）+ 行卡片（单元格失焦解析：''→null、[/{ → JSON、true/false、数字）。
