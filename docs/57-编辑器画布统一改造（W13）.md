# 编辑器画布统一改造（W13）

> 日期：2026-10-28 · 状态：已实施（全量门禁与浏览器证据见 §8） · 关联：docs/53 §13.3、docs/54 W7.3、docs/56（v4.1 题型内视图）
>
> 一句话：把「题型 → 表现」补成真画布，并让它与「画布」Tab 共用同一个 `CanvasEditor`；恢复 v4 重写时丢失的组件面板列表；画布按可用宽度自适应缩放；编辑器 Tab 名从「舞台」改回「画布」。

## 1. 背景：四个具体问题

| 问题（用户反馈） | 代码事实 | 根因 |
|---|---|---|
| 「表现」是不是画布？为什么没有可视画布？ | 改造前 `TypesTab.tsx` 的 `SurfacePane` 是**组件卡片列表**（名称/可见/X-Y-W-H/初始 props/绑定），没有画布 | W7.3 只实现了 shell 画布，surface 画布化一直登记为缺口（AGENTS「v4 已知缺口：题型 surface 仍为列表编辑」）；不是有意删功能，是分批实施欠账 |
| 「舞台」为什么把左侧组件列表删了？ | 改造前 `ShellTab.tsx` 左栏只有「下拉选类型 + 一个添加按钮」+ 提示文字 | v4 重写时把 v3 的分组组件库（音乐/交互/隐形三组按钮）压缩成了下拉，并丢了「本视图组件」清单 |
| 编辑区域为什么不随属性 / AI 面板调整？ | 改造前 `.v4-shell-canvas` 是**固定 800×470 内联尺寸** + 外层 `overflow:auto`；窗口再宽也留白，属性栏/AI 面板出现只会挤窄滚动区 | v3 画布是 `width:100%`；v4 为了 WYSIWYG 用了固定尺寸，但没有 fit-scale |
| 为什么「画布」改名「舞台」？ | v4 用运行时术语「舞台（stage）」统称 800×470 播放面，编辑器 Tab 一起改了 | 运行时概念泄漏进编辑器 IA；作者熟悉的 v3 词汇是「画布」。内部 id `shell` 与运行时舞台概念无需改名 |

## 2. 裁决

1. **两个画布同源**：新增 `src/editor/v4/CanvasEditor.tsx`，shell 画布与 surface 题内画布共用同一套组件面板/视图条/画布/属性检查器；两层差异只经 props 注入（绑定根、预览环境、视图可见性、上限、视图删除语义）。
2. **恢复组件面板列表**：按 `contract.category` 分组（音乐/交互/隐形）的快捷添加按钮 + 搜索 + 「本视图组件」清单（点击选中）；新增组件默认落在当前视图的下一个 3×3 格位（保证在 800×470 内）。
3. **画布 fit 自适应**：按视口宽度等比缩放（40%–150%），ResizeObserver + rAF 合并；属性栏开合、AI 面板开合、窗口缩放都会触发重算。指针坐标按 `design = (client - rect.left) / scale` 换算回 800×470 设计坐标。
4. **选中改到 pointerup**：属性检查器「选中才出现」；如果 pointerdown 就选中，拖拽过程中属性栏出现会改变画布宽度 → 触发缩放 → 落点漂移。现在拖拽/缩放落点 commit 后才选中，属性栏随后出现并带动一次缩放。
5. **Tab 名恢复「画布」**：`V4_EDITOR_TABS` 的 `shell` label = 画布；内部 id `shell` 不变；运行时播放面（`LevelStageV4`）仍叫「舞台」，两者不再混用。题型子页保留「表现（surface）」概念名，画布标题为「题内画布（surface）· 题型名」。
6. **surface 新增组件默认归当前题内视图**（有视图时）；无视图时 = 所有视图可见。这是对改造前「新增即所有视图可见」的一处有意调整，检查器可改回「全部视图（常驻）」。

## 3. 设计

### 3.1 组件边界

```
ShellTab.tsx（薄适配器）          TypesTab.tsx → SurfacePane（薄适配器）
        \                              /
         \                            /
           CanvasEditor（唯一画布实现）
             只读：components / views / limits / previewEnv / bindingRoots
             写：onAddComponent / onUpdateComponent / onRemoveComponent /
                 onAddView / onRenameView / onRemoveView / onSetInitialView
                            │
                            ▼
       适配器调 docStateV4 纯函数 → EditorPageV4.update(next, tag)（单一写入口 + 撤销栈）
```

`CanvasEditor` 不构造 `LevelDocV4`、不原地改组件；错误（上限/非法视图）由 docState 抛出后画布内 `v4-canvas-error` 显示。

### 3.2 两层差异（props 注入，UI 一致）

| 能力 | shell「画布」 | surface「题型 → 表现」 |
|---|---|---|
| 绑定根 | `v / run` | `q / q.state / t / args / v / run` |
| 预览数据 | flow.vars 初值 + 空 run 投影 | 题型表「预览行」的 q + q.state/typeState/args 初值 + flow.vars |
| 视图过滤 | `component.view ?? 初始视图 === 当前视图` | `component.view` 缺省 = 所有视图可见；否则仅归属视图 |
| 新增归属 | 当前视图 | 当前视图（无视图时 = 所有视图可见） |
| 视图删除 | 级联删除其组件；至少留 1 个视图 | 组件不删、归属清空为「所有视图可见」；可删到 0（回到无视图形态） |
| 预览行 | 无 | 工具栏右侧「预览行」选择器（默认首条非草稿行，草稿标注） |
| 上限 | 64 组件 / 16 视图 | 32 组件 / 16 视图 |
| 撤销 tag | `shell` | `component`（复用 `V4_TAGS.component`） |

### 3.3 画布 fit

- 纯函数 `computeCanvasFit(width)`：宽 0/非法 → 1（jsdom 首帧不抖动）；否则 `clamp(width / 800, 0.4, 1.5)`。
- 画布外层 `.v4-canvas-frame` 提供 `800×scale × 470×scale` 的布局尺寸，内层 `.editor-canvas` 以 `transform: scale() scale-origin:0 0` 缩放；`data-scale` 暴露给测试/视觉矩阵。
- 高度随宽度等比；窗口过矮时视口内部滚动（与运行时舞台按宽度 fit 一致）。编辑视图是设计坐标系视图，不等于运行时 1:1 像素。

### 3.4 组件面板 / 视图条 / 检查器

- 面板：分类快捷添加（`v4-canvas-add-<type>`）、搜索（显示名/type）、本视图组件清单（`v4-canvas-item-<id>`）、错误区、坐标提示。
- 视图条：chips（选中/重命名逐键写入/设为初始/删除）+ `+ 视图`；surface 无视图时显示说明 + 添加入口。
- 检查器（选中才出现）：名称、可见、视图归属（surface 多「全部视图（常驻）」选项）、X-Y-W-H（w/h 钳制 800/470）、初始 props JSON（`JsonEditModal`）、只读绑定（槽位来自 `DATA_APPLY_COMMANDS[type]`，实时 `checkV4Expr({roots})`）、删除。
- 检查器按组件 id `key` 重挂，待编辑绑定槽位/JSON 草稿不会串到新组件。
- Delete/Backspace 删除选中组件（复用 `keyGuard.deleteTargetBlocked`，输入框/弹窗/按钮聚焦时放行给控件）。

### 3.5 预览环境（与运行时同口径）

- 从 `runtime/v4/session.ts` 抽出 `initStateObject` / `questionContentOfRow` 到 `engine/v4/model.ts`，session 与编辑器预览共用，避免两处口径漂移。
- `canvasPreview.ts`：`buildShellPreviewEnv` / `buildSurfacePreviewEnv` / `mergeBoundProps` / `applyBoundCommands`（命令型槽位 `choice.options`、`staff.music` 在 `store.init` 后补发，预览不再是空白）。
- 绑定求值失败保留静态 props（实时错误由检查器显示），不中断预览、不产生运行副作用。

## 4. 数据与接口

- **无 `LevelDocV4` schema 变更**，不改 `schemas/v4/level.json`、validate/lint/runtime/AI 工具。
- 编辑器内部接口：`ShellTab`/`TypesTab` 对外 props 不变；新增 `CanvasEditor` / `canvasPreview` 内部模块与共享纯函数（engine）。
- 锚点契约（G3）统一为 `v4-canvas-*`，两层共用；外壳根锚点保留 `v4-shell-tab`、`v4-type-surface`、`v4-type-subtab-surface`。
  `v4-canvas`（`data-layer`）、`v4-canvas-palette/-search/-add-<type>/-item-<id>`、`v4-canvas-views/-view-<id>/-view-name-<id>/-view-initial-<id>/-view-remove-<id>/-view-add`、`v4-canvas-viewport/-stage/-scale/-box-<id>/-resize-<id>/-empty/-error`、`v4-canvas-inspector/-name/-visible/-view-field/-layout-x|y|w|h/-props-edit/-props(+-text/-apply)/-binding-*/-remove`、surface 额外 `v4-canvas-preview-row`。

## 6. 边界与失败模式

- surface 无视图：不显示 chips，显示添加入口；组件全部可见；检查器隐藏「所属视图」。
- shell 删除最后一个视图：按钮禁用（docState 亦 no-op）；surface 删到 0：归属清空、initialView 清理。
- 视图/组件被 undo/AI 外部改掉：当前视图派生回落首视图；选中 id 不存在则检查器关闭。
- 上限：添加按钮禁用；竞态下 docState 抛错 → `v4-canvas-error` 中文提示。
- jsdom 无布局：scale 回退 1，拖拽/缩放断言落点不变旧口径。
- 绑定非法：逐槽报错、预览保留静态 props。
- 切换题型：`SurfacePane` 按 typeId 加 key，画布编辑态重置。

## 7. 非目标

- 不改 LevelDoc schema/运行时/预览 Tab/AI 工具；AI 提示词里的 shell/舞台运行时术语不改。
- 不做手动 zoom 滑杆（自动 fit 已够；区间 40%–150%）、多选/标尺/对齐线/组件复制粘贴。
- 不在 shell 画布叠加另一层半透明参照（运行态才两层叠加）。
- 编辑器移动端适配仍不在范围。

## 9. 风险与后续

- AI 面板 + 属性检查器同时打开时画布会按剩余宽度缩小（fit 下限 40%）；这是可用宽度的函数，后续可做面板折叠/抽屉（本轮不做）。
- 两个画布测试共用 `v4-canvas-*` 锚点，后续新增交互需同时考虑两层；`data-layer` 可用于区分。
- 编辑器「内容」页等仍保留少量 v3 时代词汇的历史章节（本轮回填了创作入门主表），后续可单独做一轮 docs 内容全面校准。
